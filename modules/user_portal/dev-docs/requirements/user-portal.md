# 独立用户门户要求

**状态：已有验收基线保留在配套计划；2026-10-18 按用户要求移除操作理由并重验下拉框对齐，管理员角色组曾按 R-074 收紧；2026-10-19 用户改为 R-075 分级验证、新增 R-076 退出主页，并以 R-077 将分类开关扩大到两个大组。** 2026-10-11 用户确认独立门户的首版功能、
范围受限管理和分步交付方向。本文是新增账号能力与应用搜索的规范来源；
实现设计见 [独立用户门户](../../../../docs/architecture/user-portal-design.md)，
执行与证据见 [门户计划](../plans/archived/user-portal.md)。

## 1. 范围与既有要求

首版为应用入口、个人账号、委派用户管理三个部分。Casdoor 是主力 IAM，
Samba AD 管理人员、组和密码；门户不保存另一套业务身份。
委派人员由部署配置授权，并不等同于所有平台管理员。

应用字段、七档图标、独立部署、外部配置、两级分组、严格过滤、语言选择/即时切换
继续由 [应用目录矩阵](../../../../dev-docs/requirements/app-catalog.md) APPCAT-R-001—R-039 约束，本文不重复编号。
账号页、管理页及结果文字沿用相同中英文规则，不支持的语言直接使用英文。
身份定位与只读属性仍遵守 [目录身份键要求](../../../../dev-docs/requirements/directory-identity-key.md) 和 IAM 契约；
目录同步、双向登出按各自现有矩阵追踪，不借本主题缩小其适用范围。

首版包含只读本人资料、密码状态、直接/间接组及权限来源；本人原密码改密、
首次/过期受限改密；范围内人员搜索、密码重置、一次交付临时密码、下次强改、
单独解锁和直接组成员增删；近期认证、操作审计及失败/同步状态。
用户退出门户时同时退出当前浏览器的 IAM 会话，采用 discovery 的原生登出端点和固定门户结果页。
退出也须遵守 R-004，不向浏览器交付门户 token；原生配置登记门户 origin。
门户先清除自己的会话；IAM 不可达或拒绝时明确显示 IAM 登出未确认，不报告全部成功。
这不要求撤销其他设备或未接入登出协议的外部应用会话。

账号停用、无原密码找回、管理员 MFA、跨应用会话列表/撤销、收藏、
访问申请、公告、邮件/短信通知是后续候选，没有首版稳定 ID。
强改必须先有可用的受限本人改密闭环，不能因 SSO 拒绝过期密码而使用户无法恢复。

## 2. 授权和对象边界

一次委派操作由同一规则覆盖操作者、动作、目标人员和适用的组范围。
动作分为查询人员、重置密码、解锁、加入成员、移出成员、读取审计；
读权或重置权不隐式附带其他写权。空范围、未配置或失效引用不形成授权。
实际名单由受管配置给出，不硬编码某个生产部门或全量人员名单。

普通目标处于目录 Provider 的人员范围（默认 OU=People），再受显式人员/目标组范围约束。
配置中的管理人员、内置域管理组、平台/文件管理、门户操作者组与目标范围组、
服务/计算机对象及额外指定身份受保护；直接和嵌套保护均生效。
定位用 anchor/SID 等稳定身份，名称只作显示，DN 只作当前寻址。
配置的授权范围不代替目录属性/对象 ACL；后台凭据不授予客户端。

客户端导航反映动作权，服务器逐请求与提交前按当前事实核验；
旧 token 组、旧网页、同名账号或多个规则片段均不能作为捷径。
本人改密的证明是原密码与本人绑定；管理员 reset 的证明是近期认证和委派权，
两者不能互相降级或绕过。公开的受限改密入口不返回用户资料、组或应用。

## 3. 写入、审计与结果

密码策略由目录执行；不能用本地密码库、通用管理员或保存明文重试绕过。
本人改密成功后重新认证门户，跨应用会话是否已撤销必须依据实际能力说明。
组成员逐项修改；继承成员不能作为直接成员删除，冲突不覆盖别人的成员关系。

目录状态、IAM 同步状态、其他应用会话状态分别呈现。
密码不能读回比较，写入超时或服务重启后的未完成记录不能认定失败/成功后自动再写。

首个 LDAP 写入上线时即具备持久审计保护。审计意图失败则不写目录；
目录成功而结果保存失败时保留真实结果并关闭后续写入。
日志只保存必要的稳定身份、规则、差异和处理结果，不保存密码及其派生值或 token。
用户只看本人的记录，审计管理员只看授权范围内的目标。
执行记录、持久化故障和反例在配套计划验收，不以本轮文档检查冒充运行通过。

## 4. 2026-10-16 已确认扩展

按扩展方案实现界面、本人姓名/显示名编辑、ANAS 创建管理员角色的全部人员管理，以及单独启用的本人域权限操作。高复杂度来自 OIDC/AD/目录 ACL、一次性确认和审计；用户已确认本人权限模型。本轮不接入邮件后端，不提供邮箱或别名写接口。

ANAS 平台管理员由受管目录角色的稳定引用识别；可管理其他平台管理员，但本人密码走旧密码 change，不能把自己移出有效管理员集合。默认组列表来自受信注册表并分类，系统和其他组进入高级视图。域级人员和分组通过操作者本人的 LDAPS 绑定执行，不使用长期全域服务凭据。

普通 LDAP 服务账号只获姓名/重置/解锁/单成员操作的特定属性或扩展权；服务、计算机和信任主体不进入人员管理。资料使用读到的版本和单对象原子值修改保护并发；LDAP 不支持跨对象事务，不能把进程锁称为全域并发保证。

R-009/013/014/015/017/040 是首版限制，因用户明确扩展字段及授权范围而退役，下列新编号表达新边界。历史实验和旧规则委派路径的拒绝反例保留；新平台管理路径不能继承旧制品通过结论。R-011/012 的完整规则约束继续适用于显式旧规则委派，平台角色路径按 R-048 及新矩阵独立授权。

## 当前浏览器的联动退出

2026-10-19 用户确认退出当前浏览器的应用，保留其他设备；随后允许独立于业务目录发布最小登出协议地址。这解决较早应用会话不属于当前 IAM 父会话的问题，不以按用户名撤销全部设备替代。只有已确认的模块原生退出接口参与清理，普通外部目录条目不能提供任意可执行请求。原生 Nextcloud/Immich 发起来源继续在双向登出计划记录，不因门户单一来源通过而宣称完整矩阵完成。

退出先删除门户本地会话，再结束中央 IAM 会话及检查各原生应用。结果未知必须留在未确认状态；重试只具备退出用途，不能读取目录或恢复身份。新增协议元数据例外仅用于退出，不能借此返回被过滤的应用内容。


用户进一步确认原生应用返回时可匿名读取最小协议元数据，以覆盖已被 IAM 注销或从未打开过门户的用户。匿名例外限于固定退出回调和退出协议，不扩展业务目录。来自其他站点的回调导航不自动执行退出，必须由用户在页面继续；可信同站点原生跳转才自动继续，并沿用门户 CSRF 机制。
