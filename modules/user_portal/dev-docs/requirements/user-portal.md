# 独立用户门户要求

**状态：首版及审查修复已完成正式制品复验，41/41 判据通过；最终基线与证据见配套计划 §11。** 2026-10-11 用户确认独立门户的首版功能、
范围受限管理和分步交付方向。本文是新增账号能力与应用搜索的规范来源；
实现设计见 [独立用户门户](../../../../docs/architecture/user-portal-design.md)，
执行与证据见 [门户计划](../plans/archived/user-portal.md)。

## 1. 范围与既有要求

首版为应用入口、个人账号、委派用户管理三个部分。Casdoor 是主力 IAM，
Samba AD 管理人员、组和密码；门户不保存另一套业务身份。
委派人员由部署配置授权，并不等同于所有平台管理员。

应用字段、七档图标、独立部署、外部配置、两级分组、严格过滤、语言选择/即时切换
继续由 [应用目录矩阵](../../../../dev-docs/requirements/app-catalog.md) APPCAT-R-001—R-039 约束，本文不重复编号。
账号页、管理页及结果文字沿用相同中英文规则，不支持的语言直接使用英文。
身份定位与只读属性仍遵守 [目录身份键要求](../../../../dev-docs/requirements/directory-identity-key.md) 和 IAM 契约；
目录同步、双向登出按各自现有矩阵追踪，不借本主题缩小其适用范围。

首版包含只读本人资料、密码状态、直接/间接组及权限来源；本人原密码改密、
首次/过期受限改密；范围内人员搜索、密码重置、一次交付临时密码、下次强改、
单独解锁和直接组成员增删；近期认证、操作审计及失败/同步状态。
用户退出门户时同时退出当前浏览器的 IAM 会话，采用 discovery 的原生登出端点和固定门户结果页。
退出也须遵守 R-004，不向浏览器交付门户 token；原生配置登记门户 origin。
门户先清除自己的会话；IAM 不可达或拒绝时明确显示 IAM 登出未确认，不报告全部成功。
这不要求撤销其他设备或未接入登出协议的外部应用会话。

账号创建/启停、无原密码找回、管理员 MFA、跨应用会话列表/撤销、收藏、
访问申请、公告、邮件/短信通知是后续候选，没有首版稳定 ID。
强改必须先有可用的受限本人改密闭环，不能因 SSO 拒绝过期密码而使用户无法恢复。

## 2. 授权和对象边界

一次委派操作由同一规则覆盖操作者、动作、目标人员和适用的组范围。
动作分为查询人员、重置密码、解锁、加入成员、移出成员、读取审计；
读权或重置权不隐式附带其他写权。空范围、未配置或失效引用不形成授权。
实际名单由受管配置给出，不硬编码某个生产部门或全量人员名单。

普通目标处于目录 Provider 的人员范围（默认 OU=People），再受显式人员/目标组范围约束。
配置中的管理人员、内置域管理组、平台/文件管理、门户操作者组与目标范围组、
服务/计算机对象及额外指定身份受保护；直接和嵌套保护均生效。
定位用 anchor/SID 等稳定身份，名称只作显示，DN 只作当前寻址。
配置的授权范围不代替目录属性/对象 ACL；后台凭据不授予客户端。

客户端导航反映动作权，服务器逐请求与提交前按当前事实核验；
旧 token 组、旧网页、同名账号或多个规则片段均不能作为捷径。
本人改密的证明是原密码与本人绑定；管理员 reset 的证明是近期认证和委派权，
两者不能互相降级或绕过。公开的受限改密入口不返回用户资料、组或应用。

## 3. 写入、审计与结果

密码策略由目录执行；不能用本地密码库、通用管理员或保存明文重试绕过。
本人改密成功后重新认证门户，跨应用会话是否已撤销必须依据实际能力说明。
组成员逐项修改；继承成员不能作为直接成员删除，冲突不覆盖别人的成员关系。

目录状态、IAM 同步状态、其他应用会话状态分别呈现。
密码不能读回比较，写入超时或服务重启后的未完成记录不能认定失败/成功后自动再写。

首个 LDAP 写入上线时即具备持久审计保护。审计意图失败则不写目录；
目录成功而结果保存失败时保留真实结果并关闭后续写入。
日志只保存必要的稳定身份、规则、差异和处理结果，不保存密码及其派生值或 token。
用户只看本人的记录，审计管理员只看授权范围内的目标。
执行记录、持久化故障和反例在配套计划验收，不以本轮文档检查冒充运行通过。

## 4. 需求矩阵（规范来源）

本矩阵是规范来源，正文是解释。两者冲突以矩阵为准。

| ID | 要求 | 验证方式 |
| --- | --- | --- |
| `PORTAL-R-001` | 门户应用搜索必须按名称或简介筛选已获准条目，不改变原目录的排序、分类归属和可见权限 | 契约 + e2e |
| `PORTAL-R-002` | 门户 OIDC 回调必须拒绝不能通过请求绑定、签名及 issuer/audience/有效期校验的认证结果 | 单元 + e2e |
| `PORTAL-R-003` | 门户必须以 immutable anchor 绑定当前 AD 人员，同名、同邮箱或 DN 复用不得替换会话所属人员 | 单元 + e2e |
| `PORTAL-R-004` | 浏览器不得取得门户的 IAM token 或后台绑定凭据，门户会话标识必须使用受保护 Cookie | 契约 |
| `PORTAL-R-005` | 门户账号写接口必须拒绝不能通过 CSRF/Origin 校验的请求 | 单元 + 契约 |
| `PORTAL-R-006` | 委派写操作必须依据受验证的 auth_time 满足配置的近期认证窗口，缺失、过期或伪造的认证时间不得放行 | 单元 + e2e |
| `PORTAL-R-007` | 门户账号 API 每次必须按当前人员状态、当前组关系和当前委派规则授权，查询失败或账号失效不得沿用旧权限 | 单元 + e2e |
| `PORTAL-R-008` | 我的账号必须提供本人实际身份字段、账号状态与可确认的密码状态/到期信息，未知信息不得伪造 | 契约 + e2e |
| `PORTAL-R-009` | 门户本人接口必须拒绝修改 mail、sAMAccountName、displayName 或 anchor | 契约 |
| `PORTAL-R-010` | 门户组信息必须区分直接成员和嵌套继承并给出可核实的授权来源 | 契约 + e2e |
| `PORTAL-R-011` | 委派用户查找、详情、计数和分页必须只暴露当前规则允许的目标人员 | 契约 + e2e |
| `PORTAL-R-012` | 一次委派操作必须由同一完整规则同时覆盖动作、目标人员及适用的目标组，不得跨规则拼接范围 | 单元 |
| `PORTAL-R-013` | 未显式配置委派范围时门户不得授予管理动作，Admins/platform_admin 身份不得形成默认账号写授权 | 单元 |
| `PORTAL-R-014` | 委派密码/成员写入必须拒绝受保护人员、服务账号、计算机及人员范围以外的目标 | 单元 + e2e |
| `PORTAL-R-015` | 门户成员写入必须拒绝受保护组、授权边界组及能间接授予受保护权限的组 | 单元 + e2e |
| `PORTAL-R-016` | 门户 LDAP 连接必须校验目录 CA 和服务器名，安全连接失败不得改用明文或关闭校验 | 单元 + e2e |
| `PORTAL-R-017` | 门户后台目录写凭据必须仅具备首版已声明动作所需的属性/对象写权，不得扩大现有共享只读或改密凭据的权限 | e2e + 审阅 |
| `PORTAL-R-018` | 本人改密必须验证原密码并仅作用于本人，原密码失败不得退化为管理员重置 | 单元 + e2e |
| `PORTAL-R-019` | 门户密码操作必须服从目录实际密码策略并准确报告策略拒绝，不以门户规则绕过目录限制 | e2e |
| `PORTAL-R-020` | 首次/过期改密必须在普通 SSO 未完成时验证原密码并只修改同一人员密码，不授予普通门户访问 | e2e |
| `PORTAL-R-021` | 管理员重置必须要求获准目标和操作理由，不要求获取目标人员原密码 | 契约 + e2e |
| `PORTAL-R-022` | 管理员临时密码必须只在该次成功响应交付，不得由后续记录查询或重试取回 | 契约 + e2e |
| `PORTAL-R-023` | 下次登录强改必须建立在首次/过期闭环实测通过之上，reset 与设置强改部分完成不得报告全部成功 | e2e |
| `PORTAL-R-024` | 解锁必须单独授权，执行时不得隐式重置密码、启用账号或延长账号有效期 | e2e |
| `PORTAL-R-025` | 原密码、新密码及其派生值不得进入持久状态、URL、日志、审计、通知或错误详情 | 单元 + 契约 |
| `PORTAL-R-026` | 密码写入无法确定结果时门户必须报告结果未知，不得自动重放或通过保存密码进行补偿 | e2e |
| `PORTAL-R-027` | 本人改密成功后门户必须使其门户会话失效并要求重新认证，不得宣称所有外部应用会话已撤销 | e2e |
| `PORTAL-R-028` | 门户分组写接口每次必须只增删一个组的一个直接人员成员，不接受组嵌套修改或替换完整成员列表 | 契约 + e2e |
| `PORTAL-R-029` | 门户不得把间接成员显示或处理为该组可直接移除的成员 | 契约 + e2e |
| `PORTAL-R-030` | 人员/组定位变化或预期成员状态冲突时门户不得写入另一对象或覆盖他人成员变更 | e2e |
| `PORTAL-R-031` | 分组操作结果必须分别表示目录写入结果和 IAM 已观察/待同步状态，不得把 AD 已保存报告为所有应用已生效 | 契约 + e2e |
| `PORTAL-R-032` | 账号操作审计必须记录操作者/目标稳定身份、动作、授权规则、请求时间与 ID、适用差异及实际结果 | 契约 |
| `PORTAL-R-033` | 门户审计查询必须限于本人安全记录或审计管理员获准的人员范围 | 契约 + e2e |
| `PORTAL-R-034` | 审计可写时门户必须记录被拒绝和失败的账号操作，不得只记录成功操作 | 契约 |
| `PORTAL-R-035` | LDAP 写入前操作意图无法持久保存时门户必须拒绝发出写入 | 单元 + e2e |
| `PORTAL-R-036` | 门户重启必须保留持久审计及未完成记录，未完成记录不得触发自动 LDAP 重放 | e2e |
| `PORTAL-R-037` | 目录已成功而结果审计保存失败时门户必须如实报告目录结果与审计异常并停止后续写入，不得宣称回滚 | e2e |
| `PORTAL-R-038` | 密码入口必须按账号、可信客户端 IP 和全局限制尝试次数，达到限制不得继续执行密码验证/写入 | 单元 + e2e |
| `PORTAL-R-039` | 未认证的密码入口失败响应不得泄露人员是否存在、是否停用或是否属于管理范围 | 契约 |
| `PORTAL-R-040` | 门户公开接口必须限于已声明的首版动作，不得提供任意 LDAP 属性、任意 DN 或任意命令写入口 | 契约 |
| `PORTAL-R-041` | 用户退出门户时门户必须使本地会话失效并发起当前浏览器的 IAM 登出，IAM 未确认登出时不得报告完整退出成功 | 契约 + e2e |
