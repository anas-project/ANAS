# 门户登录页 IAM 会话检查

2026-10-30 用户确认登录页主动检查当前浏览器在 IAM 的登录状态，并要求同步需求、开始实施。门户现有会话存在时直接使用；没有门户会话时，通过 OIDC 无交互授权确认 IAM 身份。后台服务不能代替浏览器携带 IAM Cookie，不新增查询所有用户会话的管理权限。

无 IAM 会话或需要交互时保留门户登录按钮；失败可重试且不得循环跳转。退出结果与密码恢复页面不自动触发检查。沿用已有 OIDC 的 state、浏览器绑定、nonce、PKCE、签名与人员准入验证，检查成功不等于新近重新认证。

本矩阵是规范来源，正文是解释。两者冲突以矩阵为准。

| ID | 要求 | 验证方式 |
| --- | --- | --- |
| PORTALSSO-R-001 | 匿名用户进入普通门户登录页时主动检查当前浏览器的 IAM 会话，已有有效授权则建立门户会话并进入首页或原目标页面 | 单元 + e2e |
| PORTALSSO-R-002 | 无会话或需要交互时停留门户登录页并保留手动登录，不重复自动检查形成跳转循环 | 单元 + 界面 |
| PORTALSSO-R-003 | IAM 检查失败提供重试提示；失败不得建立门户会话 | 单元 + 界面 |
| PORTALSSO-R-004 | 退出结果页和密码恢复页不自动检查 IAM，已有门户会话不重复发起检查 | 界面 |
| PORTALSSO-R-005 | 自动检查沿用单次 state、浏览器绑定、PKCE、nonce、签名及人员准入验证，不提升近期认证时间 | 单元 |
