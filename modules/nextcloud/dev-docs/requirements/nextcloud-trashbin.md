# Nextcloud 回收站配置验收要求

本主题只使用 Nextcloud 官方系统参数，验收进度见[配套计划](../plans/nextcloud-trashbin.md)。
配置说明见[技术文档](../../docs/technical.md)。

## 配置与运行行为

`files_trash_delete` 映射为官方 `files.trash.delete`，默认布尔值 `false`。
`trashbin_retention_obligation` 默认字符串 `60,365`，允许 `disabled` 关闭自动清理。
启动任务通过 occ 写入，两项类型必须准确，失败不能标记服务就绪。

真实运行验收先核对配置，避免测试主动写入默认值而掩盖启动任务遗漏。临时用户通过认证的
WebDAV 上传并删除文件后，文件必须进入回收站；禁止手动删除时单项和清空操作均返回 403，
且回收站文件仍存在。401 等认证失败不能作为权限限制成功的证据。还原后文件内容必须保持一致。
允许手动删除时，单项删除和清空必须成功，随后列表证实内容消失。

保留期边界由运行容器内真实 Expiration 服务读取当前配置，使用合成的 59、61、366 天时间戳
检查最短期、配额清理和最长到期行为；`disabled` 下这些时间戳均不应过期。本轮不修改宿主时钟、
回收站数据库或文件名，不把这种运行时检查声称为“已等待 365 天并由 cron 删除真实旧文件”。

## 测试边界

仅在显式指定的专用测试 Docker socket/data root 和 workspace deployment 内执行。临时用户具有
随机 ID；测试结束或断言失败都恢复原配置并删除本次临时用户，恢复失败使测试失败。
密码仅通过 stdin 传递，不进入命令参数或报告；报告以 0600 保存，只记录断言结果。

## 需求矩阵

| ID | 要求 | 验证方式 |
| --- | --- | --- |
| `NCT-R-001` | 模块默认配置及运行配置必须为布尔 `files.trash.delete=false` 和字符串 `trashbin_retention_obligation=60,365` | 单元 + e2e |
| `NCT-R-002` | 启动任务必须通过 occ 按原生类型应用两个配置，并在任一写入失败时阻止就绪 | 单元 |
| `NCT-R-003` | 禁止手动删除时已认证用户的单项永久删除和清空请求必须返回 403，回收站内容保持存在 | e2e |
| `NCT-R-004` | 禁止手动删除不得阻止还原，还原后内容与上传时一致 | e2e |
| `NCT-R-005` | 通过 occ 启用手动删除后，单项永久删除和清空必须成功且列表证实内容消失 | e2e |
| `NCT-R-006` | 运行容器的 Expiration 服务必须按当前保留期处理合成时间戳，disabled 时不判定过期 | e2e |
| `NCT-R-007` | 回收站 E2E 必须在任何变更前拒绝生产 Docker socket/data root 和不属于指定 workspace 的容器 | 单元 + e2e |
| `NCT-R-008` | 回收站 E2E 成功或断言失败均必须恢复原配置并删除临时用户，清理失败必须使测试失败 | 单元 + e2e |
| `NCT-R-009` | 回收站 E2E 不得把密码写入命令参数或报告，报告文件必须为 0600 | 单元 + e2e |
