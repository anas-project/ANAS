## Ownership and data model

`store/schema.sql` defines personnel/group anchors, mailboxes and the global address table. Mailbox, protocol login, storage reference and Roundcube user keys are separately random, independent of directory anchors, names and email addresses. A primary-mailbox unique constraint and per-anchor transaction lock preserve existing resources on repeated reconciliation. The normalized global address primary key covers active ownership and reservations. Renaming is unimplemented. Go authenticates personnel through OIDC and live directory checks. The formal coordinator consumes AD mailbox_id values rather than using `EnsurePrimary` to create another directory authority.

New resources remain `pending`; directory state starts as `unknown`. Saved records grant no access. Ordinary removal retains address ownership. Only the bounded internal transaction described below accepts an exact durable transfer proof; there is no general address-delete interface. Admission anchors and the read-only company directory are wired; live multi-client convergence remains to be accepted. No phase-two shared contacts are created.

Unknown versions or source drift block startup. Every recorded version must be contiguous and match its checksum. Unknown versions, historical drift and missing intermediate records block startup. `sessions.sql` is v2, `login_flows.sql` v3 and `iam_logout.sql` v4 and `webmail_handoffs.sql` v5 and `mailbox_projection.sql` v6, `protocol_credentials.sql` v7 and `submissions.sql` v8 and `revocation_tasks.sql` v9; previously applied migration text/checksums remain unchanged.

`store/session.go` is the internal persistence layer for M2. Callers must first verify OIDC and current directory admission, then cap expiry by the verified upstream token and application policy.
