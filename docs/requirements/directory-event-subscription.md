# Samba 目录事件订阅与实时同步要求

本文规定 IAM Provider 和所有直接使用 LDAP/LDAPS 的 Module 如何消费 Samba AD 变更。Samba AD
仍是业务用户、组、账号状态和目录属性的唯一事实来源；事件日志只负责缩短变更传播时间，不成为
第二份目录数据。

## 1. 适用范围

以下消费者必须接入 Samba 发布的持久目录事件日志：

1. 所有提供通用 `iam` Capability 的 IAM Provider；
2. 所有直接通过 LDAP/LDAPS 读取 Samba 用户、组、账号状态或目录属性的 Module。

使用 LDAP 仅执行管理员发起的即时目录写操作、且不保存目录缓存或影子状态的工具，也必须订阅事件；
它可以通过失效当前查询缓存、刷新授权视图或重新读取受影响对象来响应，而不能因“下次页面请求会查
LDAP”而豁免。仅消费 IAM Token/Assertion、完全不连接 LDAP 的应用不属于本要求范围。

## 2. 消费与一致性语义

每个消费者必须只读挂载 Samba 发布的规范化持久 JSONL 日志，并维护自己的持久游标。消费者不得
要求 Samba 持有它的 API Secret，也不得让 Samba 主动回调应用。消费者必须处理相关 `Add`、
`Modify`、`Delete` 事件，并根据自身使用的属性过滤无关噪声；用户、组成员关系、嵌套组、账号启停、
改名、身份锚点以及该 Module 实际读取的 profile 属性都属于相关变更。

收到相关事件后，消费者必须在自身声明并经测试验证的最大传播时间内完成增量刷新、缓存失效或一次
受控 Source Sync，使后续认证、授权和目录视图使用最新 Samba 状态。事件突发可以防抖和合并，但
不得无限延迟；文档只写“实时同步”而没有最大传播时间和 E2E 结果，不算满足本要求。

事件路径是低延迟加速器，不是唯一一致性路径。每个保存目录缓存或影子状态的消费者必须保留周期
LDAP 全量同步或等价的全量 reconcile，修复日志保留期溢出、游标损坏和消费者长时间离线造成的缺口。
不保存目录状态的消费者仍须在事件处理失败后重试，并在下一次读取时绕过可能过期的缓存。

## 3. 可靠性、安全与验收

游标只能在对应变更已经成功刷新或明确判定与本消费者无关后提交。日志轮换、进程重启、不完整尾
记录、重复事件和同步失败不得造成静默丢失或重复同步风暴；检测到游标落后于日志保留窗口时，必须
执行全量 reconcile 后再建立新游标。

事件记录只携带定位与过滤所需的 DN、操作类型和属性名，不得携带密码、属性值、Bind Secret 或
应用 API Secret。日志对消费者只读，消费者进程使用非 root 身份，并为防抖、重试、游标重置和
全量兜底留下不含敏感值的可审计记录。

真实 E2E 必须按消费者验证：新增、修改、删除、停用、直接与递归组变更在最大传播时间内生效；重启
后从游标继续；事件突发被合并；越过日志保留窗口后由全量 reconcile 收敛。不能只断言已调用同步
API，必须检查最终认证、授权或目录视图结果。

## 4. 需求矩阵

本矩阵是规范来源，正文是解释。两者冲突以矩阵为准。

| ID | 要求 | 验证方式 |
| --- | --- | --- |
| `DIRSYNC-R-001` | 所有 IAM Provider 必须订阅 Samba 持久目录事件日志，不得只依赖定时同步、登录查询或人工 reconcile | 契约 + e2e |
| `DIRSYNC-R-002` | 所有直接使用 LDAP/LDAPS 的 Module 必须订阅 Samba 持久目录事件日志；完全不连接 LDAP 的 IAM Consumer 不在此范围 | 契约 |
| `DIRSYNC-R-003` | 每个消费者必须只读事件日志并维护独立持久游标，Samba 生产者不得持有消费者凭据或主动回调消费者 | 单元 |
| `DIRSYNC-R-004` | 消费者必须处理相关 `Add`、`Modify`、`Delete`，覆盖其使用的用户、组、嵌套组、账号状态、改名、身份锚点和 profile 属性 | 单元 |
| `DIRSYNC-R-005` | 每个消费者必须声明最大传播时间，并通过真实最终认证、授权或目录视图 E2E 证明相关变更在该时间内生效 | e2e |
| `DIRSYNC-R-006` | 防抖和最小调用间隔可以合并事件，但不得超过消费者声明的最大传播时间 | 单元 + e2e |
| `DIRSYNC-R-007` | 保存目录缓存或影子状态的消费者必须保留周期 LDAP 全量同步或等价全量 reconcile 作为一致性兜底 | 单元 |
| `DIRSYNC-R-008` | 游标只能在刷新成功或事件明确无关后提交；同步失败必须保留待处理事件并重试 | 单元 |
| `DIRSYNC-R-009` | 日志轮换、重启、不完整尾记录和重复事件不得造成静默丢失或重复同步风暴 | 单元 + e2e |
| `DIRSYNC-R-010` | 游标落后于日志保留窗口时必须先完成全量 reconcile，再从有效位置建立新游标 | 单元 + e2e |
| `DIRSYNC-R-011` | 事件不得包含密码、目录属性值或 Secret；日志只读挂载，消费者以非 root 身份运行 | 单元 |
| `DIRSYNC-R-012` | 每个消费者的真实 E2E 必须覆盖新增、修改、删除、停用、直接/递归组变更、突发合并、重启续读和保留窗口缺口恢复，并断言最终结果而非仅触发同步 API | e2e |
