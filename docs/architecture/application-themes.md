# 应用图标与可导入主题

本文说明已确认的图标来源、主题导入和 Casdoor 投射边界。要求与执行结果分别维护在
[需求矩阵](https://github.com/anas-project/ANAS/blob/master/dev-docs/requirements/application-themes.md)及
[实施计划](https://github.com/anas-project/ANAS/blob/master/dev-docs/plans/archived/application-themes.md)。当前模型已实现；最终制品与finance验收结果以配套计划为准。

## 图标与主题包

原始主题优先采用官网或官方仓库高清素材，矢量按原样渲染；没有可用高清源时按原图重绘。
每个 Module 的原始图标仍由其 `applications.icons.source` 声明。统一风格图标及配色构成第二套内置主题，
原始与统一风格均可导出为同一结构化 JSON 主题包。包内只放主题信息、受控颜色值和 PNG 源图，不加载外部资源或代码。
七档尺寸由现有目录图片缩放机制生成，仍采用内容摘要寻址。

主题包用固定 schema 和稳定 ID，明确版本、显示名、配色和出处。导入时限制请求体、图片数量、编码长度及解码像素，
拒绝未知字段和不符合格式的内容；校验完成后原子写入私有主题目录。同一内容重复导入保持一致，同名不同内容报冲突。
库目录损坏不覆盖原件；不可用主题不进入选择列表。导入不是发布动作。

## 门户与个人偏好

主题管理复用当前 ANAS 管理员角色和 CSRF。账号偏好新增独立图标主题引用，现有 `theme` 仍表示系统/浅色/深色。
普通用户看到主题名称和配色，不取得包内的应用全集；图片仍经所属应用的原生授权路径读取。
部分图标缺失时沿用原始图标；不可用个人引用回退全站默认并给出提示。
主题持久文件进入现有门户 data 卷，不增加数据库、同步进程或长期高权 IAM 凭据。

## 全站默认与 Casdoor

全站默认属于 ANAS 应用目录配置。内置主题使用稳定 ID，自定义主题引用配置目录内的主题包；
计划摘要纳入该包内容，渲染后把生成图片冻结到现有共享应用目录。门户与 Casdoor 从同一份冻结图片取值。
Casdoor Hook 继续只设置原生 Application 的 logo 字段，不加入新 Provider 补丁。

门户管理员可以导出主题包及可审阅的配置示例，再由既有 ANAS 配置/apply 路径设置全站默认。
门户不能写宿主 workspace、执行 apply 或修改 Casdoor 全站配置；个人切换不会触发这些动作。
因此无需在“门户主题库”和“Casdoor 数据库”之间运行后台同步或保存 IAM 管理写凭据。

## 来源与生成

Module 的 `assets/icon-source.json` 是原始素材出处与生成输入的单一记录：官方文件URL、原件SHA256、是否重绘、SVG/PNG摘要。原件和必要重绘SVG随Module保存；统一简约SVG在 `internal/apptheme/artwork/`。`scripts/application-themes.mjs --render` 用已有Playwright渲染PNG并生成两套包；`--check` 校验所有声明入口、摘要和包内容。运行时不加载SVG或访问来源URL。`internal/apptheme` 统一包校验与PNG规范化；内置包只在每个进程首次使用时解析和规范化。

## 实现边界

`themes/*.json` 与账号偏好使用同一私有卷；同ID同内容幂等，不同内容拒绝覆盖。配置冻结的全站自定义ID不能被可写库同名条目遮蔽；列表以冻结名称/配色为准，没有库原件时不显示导出链接。主题列表只输出名称和配色等选择信息，完整图片键和来源只允许管理员导出。个人选择失效时显示全站默认和页内恢复按钮，保存其他偏好时修复原有失效引用，但仍拒绝新提交的未知ID。

首次给Module补齐静态图标会改变模块制品。原生数据库保护可能扩大依赖重启范围，不能只从渲染差异推断停机范围；主机操作仍应使用完整恢复点和原生计划/事务。后续仅门户镜像修复已验证可只重建门户，配对计划记录具体基线和结果。

## 原生 IAM 展示修正（2026-10-22）

声明由15个入口补充为16项，新增隐藏门户品牌；不会增加可见卡片。原图保持方形，各输出尺寸使用18%半径圆角，Casdoor选512px且登录logo显示80px。主题导出仅归一原图，避免重复导入造成二次缩放或透明度损失。门户仅在导航时传原生明暗参数；图标全站/个人边界不变。
