# Research

This section contains external investigation, candidate comparison, and technical selection only. Requirements, architecture, implementation plans, dated reviews, operating procedures, and development standards live in their own sections.

- [Mail servers and ANAS integration](/research/mail-server-anas-integration-research) — Chinese original, evidence as of 2026-10-16. Compares ten mail servers/stacks for one primary address plus personal aliases sharing one inbox, AD/OIDC, self-service address management, stable identity, licensing, deployment and recovery. DMS and Stalwart are suggested for initial PoCs; no image pull, interoperability, resource or real-host acceptance is claimed.

- [Casdoor application catalog and filtering](/research/casdoor-app-catalog) — Chinese original. Twelve isolated tests execute the pinned source's permission/list functions: user/group/role filtering, OR groups, policy defaults, admin bypass and membership removal. This is source evidence, not HTTP/browser or deployment acceptance. The proposed full catalog needs API/UI work beyond native Application fields.

- [User portal identity and directory capabilities](/research/user-portal-identity-capabilities) — Chinese original. Fixed Casdoor supports secret-free PKCE, current self-account/group/policy reads with user tokens, configured reauthentication with signed auth_time checks, and current-browser OIDC logout. Application credentials remain broad; max_age/prompt alone reuse old authentication, get-user can hide state, and enforce alone ignores disabled/pending policies. No new Casdoor patch is added. Fixed Samba supports old-password change for first-login/expired accounts, scoped ACLs and GUID/SID single-member operations; assertion controls are unsupported, ACLs do not bound member values, and cross-object races remain. Evidence is in the paired plan; portal product acceptance remains unexecuted.

- [Docker and Podman compatibility](/research/docker-podman-compatibility) — Chinese original. Proposes retaining Docker CLI and Compose against a local Linux rootful Podman API. Engine identity, macvlan, Incus control networking, SELinux and reboot behavior require validation. No host compatibility or E2E acceptance is claimed; rootless full-stack operation and in-place engine migration are outside the initial scope.

- [Casdoor directory subject feasibility](/research/casdoor-directory-subject) — Chinese original. Pinned-source tests show configuration cannot unify token, UserInfo, Logout Token and SAML subjects. Revision r10 integrates the common directory-anchor subject and rejects missing anchors. Consumer projection and deployment E2E remain required; no account migration is needed before initial release.

- [Mail management layer and portal integration](/research/mail-management-layer-feasibility) — Chinese report, updated 2026-10-25. The user selected Go as the unified mail authentication, authorization and Web management service, with both primary-mailbox aliases and independent additional mailboxes. Roundcube uses a login handoff to Go; DMS validates mailbox-scoped credentials through Go, and sender decisions also come from Go. This replaces the earlier recommendation for Roundcube to connect directly to IAM; only Go connects to the existing IAM/AD identity facilities. AD owns active personal addresses; the shared PostgreSQL Provider stores mailbox ownership, address-to-mailbox mappings, operation state and mail sessions. The person's primary address remains system-derived, with future `sAMAccountName` changes reserved for only. The isolated Go-based PoC now passes 20/20 confirmed criteria, including real UI alias sending, company-directory queries, existing-session revocation and stopped recovery with a retained queue. Shared contacts remain phase two. Formal cross-Module requirements and a proposed plan now live under dev-docs/; the developing `modules/mail/` M1 foundation has started, with database/Hook/session storage checks; no complete mail service or login entry is available. Cross-system operation recovery, outage handling, least privilege and production lifecycle remain unimplemented. Historical native PoC failures retain their original baseline.
- [Webmail UIs with DMS and ANAS](/research/self-hosted-webmail-ui-research) — Chinese report, evidence as of 2026-10-23. Compares Roundcube, SOGo, Nextcloud Mail, MailFlow, SnappyMail, Cypht and Afterlogic for UI, activity, aliases, SSO, stable identity, stack reuse and recovery. Keep Roundcube as the tested baseline; compare SOGo and Nextcloud Mail, with MailFlow as a modern UI experiment. No candidate has demonstrated every ANAS requirement; no new mail deployment or acceptance is claimed.
- [Hosted mail integration, personal aliases and Module access](/research/mail-routing-alias-and-module-access) — Latest scope on 2026-10-24 removes Cloudflare + Gmail IMAP and direct full-message delivery to NAS. Supported receiving designs persist in Worker/R2 or a self-managed cloud relay before NAS HTTPS retrieval, with optional notification-only webhooks and 60-second polling. SMTP2GO/Resend sending remains independent. Public TCP 25 checks apply only to a self-managed cloud SMTP endpoint. Sections 12–16 and the linked architecture Tutorial cover prerequisites, limits, receipts and recovery. Isolated Worker/R2 and self-managed cloud relay subsets have since been tested; the paired implementation plan records exact sources, failures and limits. These are not formal Module acceptance. Historical comparisons remain separated.
- [LLNG versus the existing Casdoor integration](/research/llng-casdoor-integration-comparison) — Chinese report, evidence as of 2026-10-23. Separates native product capabilities from current Module integration: portal API and public-client/reauthentication gaps, directory revocation, SAML anchors, recovery administration, UI customization and passwordless options. Passkey is supported by pinned LLNG 2.23.2 but is not enabled or accepted in ANAS. No IAM migration or passwordless rollout is performed.
- [Cloudflare Email Routing and hosted alternatives](/research/hosted-email-forwarding-services-research) — Updated 2026-10-26. Section 9 checks providers mentioned in the supplied Reddit thread and Plunk against current pricing and public signup forms. Plunk Cloud offers 1,000 free emails/month with SMTP and branding; self-hosting requires AWS SES. Resend Free now allows three domains; Mailumi Free excludes SMTP; Maileroo needs production review and has regional availability limits. SMTP2GO exposes a phone/SMS verification path. No account was created and no provider's complete signup-country allowlist or successful +86 SMS delivery was verified. Receiving choices remain Worker/R2 or self-managed cloud staging; Gmail IMAP and direct NAS forwarding remain withdrawn.
- [LLNG and Samba AD native password changes](/research/llng-samba-password-change) — Chinese research, updated 2026-10-23. Native LLNG 2.23.2 supports mandatory and expired-password changes over verified LDAPS. The Module now enables both flags in initial and persisted startup configuration. Real Chromium/Vikunja tests preserve the original OIDC state and establish an application session after signing in again with the new password. No automatic SSO at password submission, full-runner deployment, SAML or production rollout is claimed.
