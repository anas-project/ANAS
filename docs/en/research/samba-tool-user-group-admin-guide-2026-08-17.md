Date: 2026-08-17

## 1. Summary and shortest workflow

Creating a person account in ANAS normally has three steps:

1. Create the user in `OU=People`.
2. Add the user to the required application, file-access, or business-role groups.
3. Add a dedicated administrative account to an administrator group only when the role requires it.

This section keeps only the shortest workflow. Docker, Samba user, and group parameters each have one authoritative explanation later in this guide. The default Samba DC container is `anas_samba_dc`; it is affected by [`global.container_prefix`](/en/reference/configuration#the-139-declared-parameters). For a customized deployment, use [Section 2](#_2-preflight-checks) to find the actual name.

### 1.1 Create Daneel Wang's regular account

```bash
# Create a regular user. Omit the password from the command line and enter it at the prompt.
docker exec -it anas_samba_dc samba-tool user add daneel.wang \
  --userou='OU=People' \
  --given-name='Daneel' \
  --surname='Wang' \
  --mail-address='daneel.wang@example.com' \
  --must-change-at-next-login
```

Parameter links: see [Section 2.1](#_2-1-command-structure-and-docker-options) for `docker exec -it` and line continuation, [Section 2.2](#_2-2-common-samba-tool-options) for shared authentication options, and [Section 3.1](#_3-1-create-a-regular-user) for every `user add` positional argument, common option, and AD attribute mapping. `OU=People` belongs to the [ANAS default directory layout](/architecture/samba-ad-user-planning#anas-directory-layout).

### 1.2 Set the display name

```bash
docker exec anas_samba_dc samba-tool user rename daneel.wang \
  --display-name='Daneel Wang'
```

See [Section 3.2](#_3-2-inspect-and-change-attributes) for all `user rename` parameters, attribute effects, and risks.

### 1.3 Add application and file-access groups

```bash
# Allow Nextcloud sign-in and write access to the public share.
docker exec anas_samba_dc samba-tool group addmembers 'APP_nextcloud' daneel.wang
docker exec anas_samba_dc samba-tool group addmembers 'FS Share RW' daneel.wang
```

See [Section 4.2](#_4-2-add-remove-and-verify-members) for the two `group addmembers` positional arguments and the add, remove, and list options. [`APP_nextcloud`](/architecture/samba-ad-user-planning#anas-app-groups) is generated by ANAS for an enabled application Module; [`FS Share RW`](/architecture/samba-ad-user-planning#anas-access-groups) is ANAS's fixed public-share write group. The single quotes are shell quoting, not part of either group name.

### 1.4 Verify the user and group relationships

```bash
# Verify the user and direct group relationships.
docker exec anas_samba_dc samba-tool user show daneel.wang
docker exec anas_samba_dc samba-tool user getgroups daneel.wang
docker exec anas_samba_dc samba-tool group listmembers 'APP_nextcloud'
```

See [Section 3.2](#_3-2-inspect-and-change-attributes) for user attributes and [Section 4.2](#_4-2-add-remove-and-verify-members) for direct membership and list options. These commands do not fully expand nested groups; continue with the parent-child checks in [Section 4.3](#_4-3-assign-access-through-nested-groups).

A newly created regular user automatically has `Domain Users` as the primary group. Do not add it manually.

Samba 4.23 prefers `samba-tool user add`. `samba-tool user create` remains a compatibility alias. Older Samba releases sometimes present the preference in the opposite direction, so automation must follow `samba-tool user add --help` on the target DC.

## 2. Preflight checks

Confirm the container, Samba version, domain, and directory structure:

```bash
docker ps --format '{{.Names}}' | grep samba_dc
docker exec anas_samba_dc samba-tool --version
docker exec anas_samba_dc samba-tool domain level show
docker exec anas_samba_dc samba-tool ou list --full-dn
docker exec anas_samba_dc samba-tool domain passwordsettings show
```

| Command or option | Meaning | Check performed |
| --- | --- | --- |
| `docker ps` | list containers | Lists running containers |
| <code v-pre>--format '{{.Names}}'</code> | output format | Prints only container names; `Names` is a Docker template field |
| `\| grep samba_dc` | filter matching text | Keeps lines containing `samba_dc`; the pipe passes the previous command's output to `grep` |
| `samba-tool --version` | show version | Prints the Samba version installed in the container |
| `domain level show` | show domain and forest levels | Shows domain, forest, and minimum DC functional levels |
| `ou list --full-dn` | list OUs with full DNs | Lists Organizational Units and complete DNs so paths such as `OU=People` can be verified |
| `domain passwordsettings show` | show password settings | Shows domain complexity, length, history, age, and lockout settings |

When invoked through `docker exec` in the default ANAS deployment, `samba-tool` operates on the DC's local AD database and does not need an administrator password in the command. For remote administration, use a dedicated administrator account, Kerberos, or protected credentials. Do not use `-U 'user%plaintext-password'`.

Record privileged group membership before changing it:

```bash
docker exec anas_samba_dc samba-tool group listmembers 'Domain Admins'
docker exec anas_samba_dc samba-tool group listmembers 'Administrators'
docker exec anas_samba_dc samba-tool group listmembers 'Admins'
docker exec anas_samba_dc samba-tool group listmembers 'FS Admins'
```

This reuses the [`group listmembers` options in Section 4.2](#_4-2-add-remove-and-verify-members). Do not use `--hide-expired` or `--hide-disabled` for a privileged baseline, or the record will be incomplete. Quote names containing spaces so the shell passes one argument.

### 2.1 Command structure and Docker options

Commands in this guide have an outer Docker command and an inner Samba command:

```text
docker exec [Docker options] <container> samba-tool <object> <action> [positional arguments] [options]
```

Example:

```bash
docker exec -it anas_samba_dc samba-tool user add daneel.wang --userou='OU=People'
```

| Fragment | Meaning | Effect |
| --- | --- | --- |
| `docker exec` | execute a command in a running container | Runs a command in an existing container; it does not create a new container |
| `-i` | interactive / keep STDIN open | Keeps standard input open so a password prompt can read keyboard input |
| `-t` | allocate a pseudo-TTY | Allocates a pseudo-terminal for normal interactive display; commonly combined as `-it` |
| `anas_samba_dc` | container name | Selects the Samba DC container; replace it when a custom prefix is in use |
| `samba-tool` | Samba administration tool | Invokes Samba's main administration utility |
| `user`, `group`, `ou` | object category | Selects the kind of directory object to manage |
| `add`, `show`, `move` | subcommand / action | Selects the operation to perform |
| `daneel.wang` | positional argument | Supplies the login name in a position whose order matters |
| `--userou=...` | named option | Supplies an optional setting by name; text after `=` is its value |
| `\` | shell line continuation | Continues one shell command on the next line; no spaces may follow the backslash |

The examples do not specify Docker's `--user`, so they use the container's default root user. Root can perform trusted local administration against the DC database. This does not grant remote ordinary users any AD privileges.

### 2.2 Common `samba-tool` options

These options are shared by multiple subcommands. Option placement can differ between Samba versions or command parsers; automation should follow the target command's `--help` output.

| Option | Full meaning | Details |
| --- | --- | --- |
| `-h`, `--help` | help | Shows help for the current command level. `samba-tool --help`, `samba-tool user --help`, and `samba-tool user add --help` expose different detail |
| `-V`, `--version` | version | Prints the Samba version and exits |
| `-H`, `--URL` | LDB URL / target URL | Selects a local database or remote directory, such as `ldap://dc.example.com`, `ldaps://dc.example.com`, or an LDB path. `ldaps://` means LDAP over TLS |
| `-U`, `--user` | authentication user | Selects the operation identity, normally `DOMAIN\username`. Do not append `%password`, which can leak through history and process arguments |
| `-W`, `--workgroup` | workgroup / NetBIOS domain | Overrides the short domain name from `smb.conf`, for example `NAS`; it is not the DNS realm |
| `-r`, `--realm` | Kerberos realm | Overrides the Kerberos realm, normally an uppercase DNS domain such as `NAS.EXAMPLE.COM` |
| `--use-kerberos=desired|required|off` | Kerberos authentication mode | Tries, requires, or disables Kerberos. Connect by DNS name, not IP address, when using Kerberos |
| `--use-krb5-ccache=<path>` | Kerberos credential cache | Selects a Kerberos credential cache and implicitly requires Kerberos |
| `-A`, `--authentication-file` | authentication file | Reads `username`, `password`, and `domain` from a protected file. The file contains plaintext secrets and needs restrictive permissions |
| `--password=<value>` | authentication password | Places the authentication password in process arguments and usually shell history; avoid it |
| `-N`, `--no-pass` | no password prompt | Suppresses the password prompt. Use it only when the target operation truly requires no password; it is not automatic authentication |
| `-s`, `--configfile` | Samba configuration file | Selects an alternative `smb.conf` |
| `-d`, `--debuglevel=0..10` | debug level | Controls diagnostic detail. Values above 1 generate substantial logs; values above 3 are mainly for developer investigation |

Local operations in the ANAS container normally need none of `-H`, `-U`, `-W`, or `-r`, because `samba-tool` reads the container's `smb.conf` and local AD database.

### 2.3 Directory terminology and abbreviations

| Term | Full name | Meaning and example |
| --- | --- | --- |
| AD | Active Directory | Directory service that stores users, groups, computers, and policy |
| AD DS | Active Directory Domain Services | The domain-service role implemented here by Samba |
| DC | Domain Controller | Server providing domain services; the ANAS module is `samba_dc` |
| LDAP | Lightweight Directory Access Protocol | Protocol used to query and modify directory objects |
| OU | Organizational Unit | A container such as `OU=People`; it organizes objects and supports delegation but grants no privilege by itself |
| CN | Common Name | A common relative DN such as `CN=daneel.wang` or the built-in `CN=Users` container |
| DC in a DN | Domain Component | A DNS-domain component. In `DC=nas,DC=example,DC=com`, DC does not mean Domain Controller |
| RDN | Relative Distinguished Name | The leftmost name of the current object, such as `CN=daneel.wang` |
| DN | Distinguished Name | The complete directory path, such as `CN=daneel.wang,OU=People,DC=nas,DC=example,DC=com` |
| realm | Kerberos realm | Usually the uppercase DNS domain, such as `NAS.EXAMPLE.COM` |
| workgroup | NetBIOS domain name | Short domain name such as `NAS`, distinct from the full DNS realm |
| `sAMAccountName` | Security Account Manager account name | Compatible login name such as `daneel.wang`; most `username` arguments refer to it |
| UPN | User Principal Name | Principal name such as `daneel.wang@nas.example.com` |
| SID | Security Identifier | Security identity referenced by ACLs. Deleting and recreating the same name produces a different SID |
| RID | Relative Identifier | Domain-relative unique part of a SID |
| ACL / DACL | Access Control List / Discretionary ACL | Defines which security principals may perform which operations on an object or file |
| GPO | Group Policy Object | Policy distributed to domain users and computers |
| PSO | Password Settings Object | Fine-grained password policy applied to selected users or groups |
| UID / GID | User ID / Group ID | Numeric Unix identities; they are not AD SIDs |
| RFC2307 | Unix attributes in LDAP | Schema for attributes such as `uidNumber` and `gidNumber` |
| Kerberos ticket | Kerberos authentication ticket | Cached authentication token that can retain old group claims after membership changes |

### 2.4 Common subcommand semantics

| Subcommand | Literal meaning | Operation |
| --- | --- | --- |
| `list` | list | Lists object summaries, such as all users or groups |
| `add` / `create` | add / create | Creates an object; in Samba 4.23, `create` is normally a compatibility alias for `add` |
| `show` | show | Displays directory attributes for one object |
| `edit` | edit | Opens object attributes in a text editor; unsuitable as the primary automation interface |
| `rename` | rename | Changes name-related attributes; supplied options determine whether it changes `sAMAccountName`, UPN, display name, or CN |
| `move` | move | Moves an object under another OU or container and therefore changes its DN |
| `delete` | delete | Deletes the directory object; same-name recreation cannot recover its SID or ACL identity |
| `enable` / `disable` | enable / disable | Enables or blocks authentication without deleting the object |
| `unlock` | unlock | Clears account lockout |
| `setpassword` | set password | Sets or resets a named user's password as an administrator |
| `setexpiry` | set expiry | Sets account-object expiry |
| `getgroups` | get groups | Returns a user's direct group memberships |
| `addmembers` | add members | Adds users, computers, or groups to the target group |
| `removemembers` | remove members | Removes members from the target group |
| `listmembers` | list members | Lists direct members of the target group |

## 3. Create and maintain users

### 3.1 Create a regular user

```bash
docker exec -it anas_samba_dc samba-tool user add daneel.wang \
  --userou='OU=People' \
  --given-name='Daneel' \
  --surname='Wang' \
  --department='IT' \
  --company='Example' \
  --mail-address='daneel.wang@example.com' \
  --description='Employee account; owner: IT' \
  --must-change-at-next-login

docker exec anas_samba_dc samba-tool user rename daneel.wang \
  --display-name='Daneel Wang' \
  --upn='daneel.wang@nas.example.com'
```

> Replace `example.com` and `nas.example.com` with the real email domain and AD realm before running the commands.

The example deliberately separates the person's name, login name, and display name:

| Information | Example | Stored as | Reason |
| --- | --- | --- | --- |
| Full name | Daneel Wang | Not one AD attribute | The full identity is represented by given name, surname, and display name |
| Login name | `daneel.wang` | `sAMAccountName` | Stable compatible login name |
| Given name | Daneel | `givenName`, set by `--given-name='Daneel'` | Stores the person's given name independently |
| Surname | Wang | `sn`, set by `--surname='Wang'` | Stores the family name independently; many LDAP clients expect `sn` |
| Display name | Daneel Wang | `displayName`, set by `--display-name` | Human-friendly UI label that does not change the login name |
| Email | `daneel.wang@example.com` | `mail` | Used for notifications or email-based sign-in; replace the sample domain |
| UPN | `daneel.wang@nas.example.com` | `userPrincipalName` | Modern AD sign-in form; the suffix normally follows the real AD realm |

Perform the addition in this order:

1. Run `user add`. The `-it` flags let the terminal prompt for and confirm a temporary password without recording it in command history.
2. Samba creates an enabled `sAMAccountName=daneel.wang` account in `OU=People` and writes the name, department, company, email, and description attributes.
3. Run `user rename` to set the display name and an explicit UPN. This modifies the existing object; it does not delete and recreate it.
4. Because the command includes `--must-change-at-next-login`, Daneel Wang must replace the temporary password at first sign-in.
5. Verify the DN, login name, UPN, names, and email before assigning the groups in Section 6:

```bash
docker exec anas_samba_dc samba-tool user show daneel.wang \
  --attributes=sAMAccountName,userPrincipalName,givenName,sn,displayName,mail,distinguishedName
docker exec anas_samba_dc samba-tool user getgroups daneel.wang
```

The verification commands do not repeat their parameters: see [Section 3.2](#_3-2-inspect-and-change-attributes) for `user show --attributes` and [Section 4.2](#_4-2-add-remove-and-verify-members) for the direct-membership semantics of `user getgroups`.

User-creation parameters:

| Parameter | Meaning | AD attribute or behavior | Notes |
| --- | --- | --- | --- |
| `daneel.wang` | username / logon name | `sAMAccountName` | Required positional argument; unique compatible login name in the domain |
| `[password]` | initial password | password credential | Optional second positional argument. The guide omits it so the tool prompts without exposing plaintext |
| `--userou='OU=People'` | user organizational unit | parent of the object DN | Creates the object in the chosen OU. The domain DN may be omitted; the usual default is `CN=Users` |
| `--given-name='Daneel'` | given name | `givenName` | Person's given name |
| `--surname='Wang'` | surname / family name | `sn` | Person's family name; some LDAP clients expect `sn` to exist |
| `--initials` | initials | `initials` | Name initials, commonly used with middle names |
| `--department='IT'` | department | `department` | Profile data only; it neither maintains [`ROLE_DEPT_*` membership](/architecture/samba-ad-user-planning#anas-department-groups) nor grants department access |
| `--company='Example'` | company | `company` | Company or organization name |
| `--job-title` | job title | `title` | Job title; changing a job should not require changing the account name |
| `--description='...'` | description | `description` | Administrative purpose or owner. Never store a password here |
| `--mail-address='...'` | mail address | `mail` | Email address; it must be unique if an application accepts email sign-in |
| `--telephone-number` | telephone number | `telephoneNumber` | Office telephone number |
| `--physical-delivery-office` | office location | `physicalDeliveryOfficeName` | Physical office location |
| `--profile-path` | roaming profile path | `profilePath` | Windows roaming-profile path; normally unused by ANAS |
| `--script-path` | logon script path | `scriptPath` | Windows logon script, normally relative to the `NETLOGON` share |
| `--home-drive` | home drive letter | `homeDrive` | Windows drive letter such as `H:`; it does not create a directory |
| `--home-directory` | home directory UNC path | `homeDirectory` | Windows home UNC path, distinct from the ANAS Samba FS Home created on first access |
| `--must-change-at-next-login` | force password change at next logon | normally sets `pwdLastSet=0` | Makes the initial password temporary |
| `--random-password` | generate a random password | assigns a random password | Useful for technical accounts. Deliver the secret separately or use a keytab; do not assume it can be read back |
| `--use-username-as-cn` | use username as Common Name | object CN | Keeps CN equal to the login name instead of deriving it from the person's name |
| `--smartcard-required` | smart card required | `userAccountControl` flag | Requires smart-card interactive logon; enable only after certificates and clients are ready |

Profile attributes such as `department` and `surname` do not grant access. Maintain department membership under the [ANAS company-department group standard](/architecture/samba-ad-user-planning#anas-department-groups); other authorization still comes from Sections 4–6.

Additional points:

- `sAMAccountName` must be unique. Use a stable naming convention based on letters, digits, dots, hyphens, or underscores.
- `--userou='OU=People'` does not need the `DC=...` suffix; Samba completes the current domain DN.
- `-it` permits an interactive password prompt without putting the password in shell history or process arguments.
- The password must satisfy `samba-tool domain passwordsettings show`.
- Use `--must-change-at-next-login` for human initial passwords, not blindly for service accounts.
- ANAS LDAP applications currently search only `OU=People`. An account moved to `OU=Admins` is outside their user search base.

Move an account created in the default `CN=Users` container:

```bash
docker exec anas_samba_dc samba-tool user move daneel.wang 'OU=People'
```

| Parameter | Meaning | Details |
| --- | --- | --- |
| `user move` | move a user | Moves the existing user under another OU or container; the SID remains but the DN changes |
| `daneel.wang` | username | First required positional argument; user to move |
| `'OU=People'` | new parent DN | Second required positional argument; target parent. The current domain's `DC=...` suffix may be omitted |

### 3.2 Inspect and change attributes

```bash
# Display selected LDAP attributes.
docker exec anas_samba_dc samba-tool user show daneel.wang \
  --attributes=sAMAccountName,userPrincipalName,displayName,mail,distinguishedName,userAccountControl

# Change the display name, email address, or UPN.
docker exec anas_samba_dc samba-tool user rename daneel.wang \
  --display-name='Daneel Wang' \
  --mail-address='daneel.wang@example.com' \
  --upn='daneel.wang@nas.example.com'
```

| Option | Meaning | Details |
| --- | --- | --- |
| `--attributes=a,b,c` | attributes to display | Prints only the comma-separated LDAP attributes |
| `--display-name` | display name | Changes `displayName`, usually without changing the login name |
| `--mail-address` | mail address | Changes `mail` |
| `--upn` | User Principal Name | Changes `userPrincipalName`; the suffix must be accepted by the directory |
| `--samaccountname` | SAM account name | Changes the compatible login name; high risk for sign-in and integrations without a permanent identity key |
| `--force-new-cn` | force a new Common Name | Explicitly changes the CN/RDN and therefore the object DN |
| `--reset-cn` | reset Common Name | Recomputes CN from given name, initials, and surname |

Replace `nas.example.com` with the real AD realm. `user rename` changes the existing object rather than deleting and recreating it, so the SID remains stable. Nevertheless, inspect LDAP clients before changing a login name or DN because some clients incorrectly treat the old DN as a permanent key. ANAS identity anchors preserve identity only for integrations that consume them.

### 3.3 Password, lock, enablement, and expiry

```bash
# Reset a password and enter it interactively.
docker exec -it anas_samba_dc samba-tool user setpassword daneel.wang

# Require a password change after the reset.
docker exec -it anas_samba_dc samba-tool user setpassword daneel.wang \
  --must-change-at-next-login

# Unlock, disable, and re-enable the account.
docker exec anas_samba_dc samba-tool user unlock daneel.wang
docker exec anas_samba_dc samba-tool user disable daneel.wang
docker exec anas_samba_dc samba-tool user enable daneel.wang

# Expire the account after 90 days, or remove account expiry.
docker exec anas_samba_dc samba-tool user setexpiry daneel.wang --days=90
docker exec anas_samba_dc samba-tool user setexpiry daneel.wang --noexpiry
```

| Parameter | Meaning | Details |
| --- | --- | --- |
| `user setpassword <username>` | set or reset password | Resets the named user's password; prompts when `--newpassword` is omitted |
| `--newpassword=<value>` | new password | Supplies the new password non-interactively, but leaks it into arguments and history; avoid it |
| `--must-change-at-next-login` | must change at next logon | Makes the reset value a temporary first-login password |
| `user unlock` | unlock account | Clears lockout caused by too many failed sign-ins |
| `user disable` / `enable` | disable / enable account | Blocks or restores authentication without deleting the SID or ACL references |
| `--remove-supplemental-groups` | remove supplemental groups | High-impact `user disable` option that removes every group except the primary group. Do not use it without exporting membership first |
| `setexpiry --days=N` | expire after N days | Sets account-object expiry N days from now |
| `setexpiry --noexpiry` | account never expires | Clears account expiry; it does not change password expiry policy |

Account expiry and password expiry are different controls. `setexpiry --noexpiry` affects `accountExpires`; the domain policy or a Password Settings Object still governs password age.

### 3.4 Deactivate and delete

Disable and deauthorize first instead of immediately deleting a departing user's object:

```bash
docker exec anas_samba_dc samba-tool user disable daneel.wang
docker exec anas_samba_dc samba-tool group removemembers 'APP_nextcloud' daneel.wang
docker exec anas_samba_dc samba-tool group removemembers 'FS Share RW' daneel.wang
docker exec anas_samba_dc samba-tool user move daneel.wang 'OU=Graveyard'
```

See [Section 3.3](#_3-3-password-lock-enablement-and-expiry) for `user disable` and the high-impact `--remove-supplemental-groups` option, and [Section 4.2](#_4-2-add-remove-and-verify-members) for `group removemembers`. `user move` uses the same argument order as the [move example in Section 3.1](#_3-1-create-a-regular-user), with the destination changed to ANAS's [`OU=Graveyard`](/architecture/samba-ad-user-planning#anas-directory-layout).

Delete only after data handover, audit, and the retention period:

```bash
docker exec anas_samba_dc samba-tool user delete daneel.wang
```

| Parameter | Meaning | Details |
| --- | --- | --- |
| `user delete` | delete a user | Permanently deletes the directory object; this is not a disable operation |
| `daneel.wang` | username | Required positional argument naming the user to delete |
| `--help` | help | Run `samba-tool user delete --help` first to confirm installed-version syntax; this subcommand normally has no business-profile options |

Deleting and recreating the same name produces a new SID. File ACLs can retain the old SID, so recreating the name does not restore access. Complete Home, Share, and other domain-resource ACL handover before deletion.

## 4. Create and manage groups

Consult the [ANAS group naming standard](/architecture/samba-ad-user-planning#anas-group-naming) before creating anything. Administrator-created department, role, project, and resource groups use stable codes. ANAS fixed groups, generated `APP_*` groups, and AD built-in groups retain their exact product or directory names and must not be recreated or casually renamed. Company departments use [`ROLE_DEPT_<COMPANY_CODE>_<DEPARTMENT_CODE>`](/architecture/samba-ad-user-planning#anas-department-groups), for example `ROLE_DEPT_ANAS_IT`.

### 4.1 Create a business-role group

ANAS organizes groups under its [default directory layout](/architecture/samba-ad-user-planning#anas-directory-layout):

- `OU=Role,OU=Groups`: business or responsibility roles.
- `OU=Access,OU=Groups`: file and other resource permissions.
- `OU=Apps,OU=Groups`: application sign-in scope.

The following command creates a project role. `ROLE_PROJECT_A` is a documentation example, not a group pre-created by ANAS:

```bash
docker exec anas_samba_dc samba-tool group add 'ROLE_PROJECT_A' \
  --groupou='OU=Role,OU=Groups' \
  --group-scope=Global \
  --group-type=Security \
  --description='Project A members'
```

| Parameter | Meaning | Attribute or behavior | Details |
| --- | --- | --- | --- |
| `ROLE_PROJECT_A` | group name | `sAMAccountName`, and normally CN | Required positional argument; quote names containing spaces |
| `--groupou` | group organizational unit | parent of the object DN | Selects the creation location; the usual default is `CN=Users` |
| `--group-scope` | group scope | scope bits in `groupType` | Accepts `Global`, `Universal`, or `Domain`; Samba's `Domain` means AD Domain Local |
| `--group-type` | group type | security bit in `groupType` | `Security` grants access; `Distribution` is for message distribution |
| `--description` | description | `description` | Records purpose, resource, owner, or approval boundary |
| `--mail-address` | mail address | `mail` | Group email address when a mail system needs one |

Group scope determines who can be a member and where the group can receive permissions:

| Samba value | AD term | Typical permitted members | Permission scope | ANAS guidance |
| --- | --- | --- | --- | --- |
| `Global` | Global group | Accounts and Global groups from the same domain | Any domain in the forest and trusting domains | Default for single-domain people roles and responsibilities |
| `Universal` | Universal group | Accounts and Global/Universal groups from any domain in the forest | Any domain in the forest and trusting forests | Use only for real multi-domain aggregation; membership is globally cataloged |
| `Domain` | Domain Local group | Accounts and several group types from trusted domains | This domain only | Useful for a resource permission local to this domain; the option value is not `DomainLocal` |

Use `Security` groups for ACLs. A `Distribution` group is not security-enabled and cannot be placed in a DACL.

### 4.2 Add, remove, and verify members

```bash
# Process one member at a time for clearer audit records.
docker exec anas_samba_dc samba-tool group addmembers 'ROLE_PROJECT_A' daneel.wang
docker exec anas_samba_dc samba-tool group addmembers 'ROLE_PROJECT_A' bob

# Inspect membership and group attributes.
docker exec anas_samba_dc samba-tool group listmembers 'ROLE_PROJECT_A'
docker exec anas_samba_dc samba-tool group show 'ROLE_PROJECT_A'

# Remove a member.
docker exec anas_samba_dc samba-tool group removemembers 'ROLE_PROJECT_A' daneel.wang
```

| Parameter | Meaning | Details |
| --- | --- | --- |
| `groupname` | target group name | First positional argument; target group's `sAMAccountName` |
| `members` | members to add or remove | Second positional argument; may name a user, computer, or group. This guide uses one per command for auditability |
| `listmembers --full-dn` | show full Distinguished Names | Prints full DNs instead of preferring `sAMAccountName` |
| `listmembers --hide-expired` | hide expired members | Omits expired accounts; normally avoid it during audits |
| `listmembers --hide-disabled` | hide disabled members | Omits disabled accounts; normally avoid it during privilege cleanup |

`user getgroups` and `group listmembers` show direct relationships, not a fully expanded effective token. Inspect each level of a nested chain and validate the real application or client result.

### 4.3 Assign access through nested groups

Add users to a business role, then nest that role under a resource group:

```bash
docker exec anas_samba_dc samba-tool group addmembers 'ROLE_PROJECT_A' daneel.wang
docker exec anas_samba_dc samba-tool group addmembers 'APP_nextcloud' 'ROLE_PROJECT_A'
```

The argument order remains “target group, member” as defined in [Section 4.2](#_4-2-add-remove-and-verify-members). The second command supplies `ROLE_PROJECT_A` as a member and therefore creates nesting. See the ANAS definition of [`APP_nextcloud`](/architecture/samba-ad-user-planning#anas-app-groups).

ANAS application filters support recursive membership. Remove the parent-child relationship to revoke the role's application access:

```bash
docker exec anas_samba_dc samba-tool group removemembers 'APP_nextcloud' 'ROLE_PROJECT_A'
```

This removes the child `ROLE_PROJECT_A` from its parent `APP_nextcloud`; users remain in the child group. See [Section 4.2](#_4-2-add-remove-and-verify-members) for `removemembers` arguments.

Do not create group cycles or nest ordinary business groups under privileged administrator groups.

### 4.4 Delete a group

```bash
docker exec anas_samba_dc samba-tool group delete 'ROLE_PROJECT_A'
```

| Parameter | Meaning | Details |
| --- | --- | --- |
| `group delete` | delete a group | Deletes the directory object and leaves its SID without a resolvable group principal |
| `'ROLE_PROJECT_A'` | group name | Required positional argument naming the group. Quotes protect spaces and shell metacharacters |
| `--help` | help | Run `samba-tool group delete --help` before deletion to confirm installed-version syntax |

A group has its own SID. Deleting it leaves that SID unresolved in file or application ACLs. Export membership, remove resource ACL entries, and confirm that no application filter references the group before deletion.

## 5. Define the administrative scope first

“Administrator” is not one permission. ANAS has several independent scopes:

| Group | Expanded meaning | Privilege | Domain administrator? | Typical use |
| --- | --- | --- | --- | --- |
| [`Domain Admins`](/architecture/samba-ad-user-planning#ad-built-in-groups) | Domain Administrators | High privilege across the AD domain | Yes | Domain, DC, user, group, and domain-wide configuration administration |
| [`Administrators`](/architecture/samba-ad-user-planning#ad-built-in-groups) | Administrators | Unrestricted built-in administrator privilege | Yes; very high risk | Low-level directory or DC administration; users normally do not need direct membership |
| [`Unix Admins`](/architecture/samba-ad-user-planning#anas-role-groups) | Unix Administrators | ANAS domain-infrastructure administration; nested under `Administrators` | Yes; very high risk | Samba/Unix domain infrastructure |
| [`Group Policy Creator Owners`](/architecture/samba-ad-user-planning#ad-built-in-groups) | Owners allowed to create Group Policy | Creates and manages owned GPOs | No | Group Policy maintenance |
| [`Admins`](/architecture/samba-ad-user-planning#anas-role-groups) | Abbreviation of Administrators | ANAS application-administrator role | No | Authentik, Nextcloud, LAM, and other application administration; AD writes still obey ACLs |
| [`FS Admins`](/architecture/samba-ad-user-planning#anas-access-groups) | File System Administrators | Root-equivalent file access on Samba FS | No, but extremely powerful | ACL repair, restore, and file-service operations |
| [`FS Share RW`](/architecture/samba-ad-user-planning#anas-access-groups) | File System Share Read/Write | Write access to the public `Share` | No | Ordinary file collaboration |
| [`APP_all` / `APP_<application>`](/architecture/samba-ad-user-planning#anas-app-groups) | All applications / named application | All or one application sign-in | No | Ordinary application access |

### 5.1 Create a dedicated domain administrator

Do not elevate the everyday `daneel.wang` account. Create a separate account:

```bash
docker exec -it anas_samba_dc samba-tool user add adm_daneel.wang \
  --userou='OU=People' \
  --given-name='Daneel' \
  --surname='Wang' \
  --description='Dedicated domain administrator for Daneel Wang'

docker exec anas_samba_dc samba-tool user rename adm_daneel.wang \
  --display-name='Daneel Wang (Domain Admin)'

docker exec anas_samba_dc samba-tool group addmembers 'Domain Admins' adm_daneel.wang
docker exec anas_samba_dc samba-tool group listmembers 'Domain Admins'
```

This section reuses [Section 3.1](#_3-1-create-a-regular-user) for creation, [Section 3.2](#_3-2-inspect-and-change-attributes) for the display name, and [Section 4.2](#_4-2-add-remove-and-verify-members) for membership and verification. `adm_daneel.wang` follows the [ANAS administrator-account naming standard](/architecture/samba-ad-user-planning#anas-account-naming). `Domain Admins` is an [AD built-in privileged group](/architecture/samba-ad-user-planning#ad-built-in-groups), not an ANAS custom group.

`Domain Admins` is already extremely privileged. Do not automatically add the account to `Administrators`, `Enterprise Admins`, `Schema Admins`, `FS Admins`, or `Admins`. Grant each independent scope only when the role requires it.

ANAS keeps human accounts that must be discoverable by LDAP applications in `OU=People`. `OU=Admins` is currently reserved and outside application user search bases. A domain administrator that will never sign in to ANAS applications may be placed there after review, with the explicit consequence that current application LDAP searches cannot find it.

### 5.2 Grant application-administrator access

```bash
docker exec anas_samba_dc samba-tool group addmembers 'Admins' adm_daneel.wang
docker exec anas_samba_dc samba-tool group listmembers 'Admins'
```

See [Section 4.2](#_4-2-add-remove-and-verify-members) for the command arguments. [`Admins`](/architecture/samba-ad-user-planning#anas-role-groups) is the ANAS application-administrator role, not the AD built-in `Administrators`; it grants neither `Domain Admins`, host root, database-superuser, nor `FS Admins` privilege.

### 5.3 Grant file-server administrator access

```bash
docker exec anas_samba_dc samba-tool group addmembers 'FS Admins' fsadm_daneel.wang
docker exec anas_samba_dc samba-tool group listmembers 'FS Admins'
```

See [Section 4.2](#_4-2-add-remove-and-verify-members) for the command arguments. [`FS Admins`](/architecture/samba-ad-user-planning#anas-access-groups) has root-equivalent file capabilities on Samba FS, and `fsadm_daneel.wang` follows the [ANAS administrator-account naming standard](/architecture/samba-ad-user-planning#anas-account-naming). Do not add an everyday account, `Domain Admins`, or an entire business group.

### 5.4 Grant GPO management or workstation-local administration

For a role that only creates GPOs:

```bash
docker exec anas_samba_dc samba-tool group addmembers \
  'Group Policy Creator Owners' adm_daneel.wang
```

See [Section 4.2](#_4-2-add-remove-and-verify-members) for the command arguments. `Group Policy Creator Owners` is an [AD built-in group](/architecture/samba-ad-user-planning#ad-built-in-groups) that permits creation and management of owned GPOs, not full domain administration.

If users only need to administer selected Windows workstations, do not add them to `Domain Admins`. Create an ordinary security group such as `ROLE_WORKSTATION_ADMINS`, then use a GPO to add it to the local `Administrators` group on the target workstations. `samba-tool group addmembers` changes AD membership; it does not directly change every computer's local administrator group.

### 5.5 Revoke administrator privileges

```bash
docker exec anas_samba_dc samba-tool group removemembers 'Domain Admins' adm_daneel.wang
docker exec anas_samba_dc samba-tool group removemembers 'Admins' adm_daneel.wang
docker exec anas_samba_dc samba-tool group removemembers 'FS Admins' fsadm_daneel.wang
docker exec anas_samba_dc samba-tool group removemembers \
  'Group Policy Creator Owners' adm_daneel.wang
```

All four commands use the “target group, member to remove” order defined in [Section 4.2](#_4-2-add-remove-and-verify-members).

Run `group listmembers` again after revocation. Existing Windows, Kerberos, or application sessions may retain an old authorization token. Sign out, clear Kerberos tickets or application sessions where necessary, sign in again, and test the real permission.

## 7. Verification and troubleshooting

### 7.1 User creation fails

Inspect installed-command help and password policy:

```bash
docker exec anas_samba_dc samba-tool user add --help
docker exec anas_samba_dc samba-tool domain passwordsettings show
```

| Command or option | Meaning | Details |
| --- | --- | --- |
| `user add --help` | show help for user creation | Prints installed-version syntax, positional arguments, and every option without creating a user |
| `domain passwordsettings show` | show domain password settings | Read-only display of domain password and lockout policy |
| `domain passwordsettings set` | set domain password settings | Common but high-impact modification subcommand; this troubleshooting workflow does not run it |
| `set --complexity=on\|off` | password complexity | Enables or disables password complexity requirements |
| `set --min-pwd-length=N` | minimum password length | Sets the shortest permitted password |
| `set --history-length=N` | password history length | Sets the number of old passwords that cannot be reused |
| `set --min-pwd-age=N` / `--max-pwd-age=N` | minimum / maximum password age | Sets minimum and maximum password age in days |
| `set --account-lockout-threshold=N` | account lockout threshold | Sets the number of failed sign-ins that triggers lockout |
| `set --account-lockout-duration=N` | account lockout duration | Sets lockout duration in minutes |
| `set --reset-account-lockout-after=N` | reset lockout counter after | Sets the minutes before the failed-attempt counter resets |

Changing domain password policy affects every user not covered by a more specific PSO. Record the old values and use change approval first.

Common causes include a duplicate login name, wrong OU path, a password that violates length, complexity, or history policy, and insufficient ACLs for the operator.

### 7.2 Group membership exists but access has not changed

```bash
docker exec anas_samba_dc samba-tool user getgroups daneel.wang
docker exec anas_samba_dc samba-tool group listmembers 'Target Group'
docker exec anas_samba_dc samba-tool user show daneel.wang
```

See [Section 3.2](#_3-2-inspect-and-change-attributes) for user-query parameters and [Section 4.2](#_4-2-add-remove-and-verify-members) for membership verification. Avoid `--hide-expired` and `--hide-disabled` when troubleshooting missing access, or the output can omit the account that needs cleanup.

Then check:

1. Whether the user is disabled or expired.
2. Whether a nested group was missed because only direct membership was inspected.
3. Whether the application uses the intended `APP_*` filter.
4. Whether the client or application retains an old sign-in session, Kerberos ticket, or group cache.
5. Whether the target Share ACL still needs an entry for the security group.

### 7.3 A user can administer an application but cannot change AD

This can be correct. `Admins` grants ANAS application administration but does not bypass AD ACLs. Use a dedicated `Domain Admins` account for domain-wide administration. If the task covers only one OU, delegate the minimum OU ACL to a dedicated management group instead of granting domain-wide privilege.

### 7.4 Do not manually assign Unix UID/GID values in ANAS

ANAS Samba FS uses deterministic `idmap_rid` mapping and does not read `uidNumber` or `gidNumber` from user objects. Do not copy generic RFC2307 tutorials that run `user addunixattrs` or `group addunixattrs`. Changing the ID-mapping backend after files exist can change Unix owner resolution and requires a separately designed and tested migration.

## 8. Security and operations requirements

1. Give every person an individual account, separating everyday, `adm_*`, and `fsadm_*` identities.
2. Do not place passwords in positional arguments or `-U user%password`. Samba recommends an interactive prompt, Kerberos, or protected `PASSWD_FD` / `PASSWD_FILE` input.
3. Review `Domain Admins`, `Administrators`, `Unix Admins`, and `FS Admins` at least monthly; review `Admins`, `APP_all`, `APP_*`, and `FS Share RW` at least quarterly.
4. Record the requester, approver, executor, reason, time, and planned revocation for every privileged-group change.
5. On departure, disable the user, remove memberships, and move it to `OU=Graveyard`; delete only after data and ACL handover.
6. Do not use `Enterprise Admins` or `Schema Admins` for daily work. Grant them temporarily only for explicit forest- or schema-change windows and remove them immediately afterward.
7. Test bulk changes on a test account and back up AD, group membership, and critical file ACLs first.
