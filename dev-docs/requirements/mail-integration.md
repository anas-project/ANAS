# 邮件 Module 与目录集成要求

本文整理用户已确认的正式邮件功能，供实现和验收使用；执行状态、待确认事项和证据见[配套计划](../plans/mail-integration.md)。本主题同时约束邮件 Module、Samba 地址维护、IAM 和门户入口，属于跨 Module 集成；实现与验收状态统一记录在配套计划。已完成的 [DMS/Roundcube PoC](../requirements/mail-webmail-poc.md)是选型实验，其结果不能替代本文的正式制品验收。

2026-10-26 用户明确取消 SMTP2GO。R-042 保留编号并废弃，一期不再提供该服务预设或要求其账号验收；发送保留 Resend 与兼容 SMTP，兼容 SMTP 的本轮用户指定实测服务为 eusend。此前选择 SMTP2GO 的记录属于历史，不再构成阻塞。

2026-10-30 用户确认地址管理迁入邮件，门户仅在建号时检测冲突；本次决定取代 2026-10-25 的“门户维护、邮件只读”，不改变 Samba 权威存储、共享占用及既有移交安全条件。

2026-10-30 用户要求基于当前邮件 Module 编写邮箱访问契约的独立需求和计划。新增的应用只读访问范围见[邮箱访问契约要求](mail-access.md)，使用 `MAILACCESS-R-*`，由[专项计划](../plans/mail-access.md)交付；本文的 `MAILMOD-R-*` 及既有结果保持原归属。受用户授权的应用读信与下文未纳入的人到人委派、共享邮箱、通用外部客户端/应用密码是不同范围；本次不因此开放后者。

## 1. 已确认范围

邮件 Module 包含 Go 管理服务及 Web 页面、docker-mailserver（下文 DMS）和 Roundcube，复用现有 PostgreSQL、IAM 和 Samba AD。用户最新明确：邮箱资源和地址归属最终也保存在 Samba，邮件 Module 负责地址管理页面、受限写入及排重，并负责本地运行投影、邮件会话、协议及发信许可；门户仅在新建用户时检查主地址冲突；不能因门户暂不可用而改用第二份人员密码。用户从 Go 页面选择邮箱后进入 Roundcube 读写邮件，不再输入邮箱密码。2026-10-25 用户进一步确认：独立邮箱是同一人员名下的邮箱资源，共用人员登录，不为每箱创建 AD 登录用户或密码。用户进一步确认采用两类非登录 AD 对象：邮箱资源保存独立 mailbox_id 并通过所属人员字段引用现有 anasIdentityAnchor；地址占用记录将默认地址或别名绑定至具体邮箱，人员 proxyAddresses 保留有效别名。邮件地址管理、门户建号及系统主地址维护共用占用规则。实现进度见计划 D4，方案确认不等于 schema 已安装或写入协调已完成。

一期支持主箱加个人别名、本人独立附加邮箱、AD 公司只读通讯录，以及目录事件和 IAM 登出引发的实际邮件撤权。个人别名允许自助增删，独立箱允许本人自助开通及管理员代办；箱数、别名数、每箱容量和发送限速须由管理员在 Tutorial 初始化时明确设置，不默认无限额。一期正式支持并分别验收 Casdoor 和 LLNG。

2026-10-24 用户确认将三类故障验收纳入一期：地址变更中断后的幂等恢复与下游生效确认、AD 读取故障期间已有撤权任务继续执行、停机/恢复失败不伪报成功且恢复后的旧会话失效。补充判据为 R-033—037，生效确认同时沿用 R-017；不新增独立服务。

主地址仅消费系统按 `sAMAccountName` 和邮件后缀派生的 AD `mail`。当前不实现 `sAMAccountName` 修改、独立改主地址或别名升为主地址。未来开放登录名修改时，新主地址仍归原邮箱，旧主地址自动成为本人同箱别名；一期仅保证身份和存储模型不依赖可变地址，不能把测试预配改址写成已实现自动迁移。

组内与全局共享联系人属于二期，一期只保留通讯录来源、查询和授权接口。群发列表、共享邮箱、委派访问、跨箱共享私人联系人、手机通讯录同步均未纳入一期。Roundcube 原生私人通讯录随其邮箱用户隔离。

2026-10-24 用户追加 Cloudflare Email Routing、SMTP2GO Free、Resend 等服务接入，纳入一期。当时 Cloudflare 承担入站转发与受管地址规则，SMTP2GO Free 和 Resend 承担经 DMS 的出站 SMTP 代发；SMTP2GO 已由 2026-10-26 的最新决定取消；其他具有兼容认证 SMTP 接口的服务可使用通用配置，未实测产品不标为已验证。具体账号、域名和网络参数仍待部署时提供，已授权独立接入验证；真实云资源、DNS 和外部测试地址按实际提供的隔离环境执行，不默认改动生产。

早期曾要求 NAS 公网 25 检测及不通时降级；2026-10-24 用户取消 NAS 直投与 Cloudflare＋Gmail IMAP，转为云端持久接收。2026-10-27 用户重新确认增加管理员明确选择的 NAS 直接收件：NAS 离线时依靠发件方重试，须提示保管与投递无法保证；不自动降级或切换。Worker/R2 与自管云仍分别保留独立持久接收和离线补取。原 R-051/R-053/R-055 的自动降级不恢复，保留废弃记录，直接收件按 R-073 新增验收。

2026-10-28 用户要求提供不依赖 Cloudflare 的 VPS 收件，并加强收件和发件的逐步配置引导与每步检查。VPS 直接作为 MX 入站，NAS 离线时暂存在 VPS；邮箱与别名仍由既有人员身份及目录管理，不把目录保存当作收发就绪。非 Cloudflare 无服务器接收需要额外邮件平台作为 SMTP 入口，用户确认 SES 方案暂不纳入一期；其他方案仅作研究，见[非 Cloudflare 接收方案](../../docs/research/mail-non-cloudflare-inbound.md)。

外部邮件客户端或 DMS 应用密码、在线备份、多 DC 和多标签页同时写不同邮箱仍未纳入一期。Resend 入站 Webhook、供应商 HTTP 发信 API、营销群发及自动切换多个免费账号不在本次接入范围；外部收信源的专用凭据不等于开放 DMS 应用密码。两种自管接收来源的新邮件通知按后述确认范围执行，不另建 SMTP 发送服务。

用户要求的云中转接入选项见[架构方案及 Tutorial](../../docs/architecture/portal-account-mail-administration.md)。一期收件方式为 NAS 直接收件、Worker/R2 和自管云；两种云来源仍由 NAS 主动拉取正文，可选 Webhook 只通知有新邮件。已有 VPS 安装与自动购机的边界、账号、容量等仍见 D7/D8。

用户已确认两种云来源都支持“推送通知，NAS 立即取信，继续每 60 秒补取”，并同意先验证 Worker/R2 的持久存信、通知超时、重复回执和 NAS 恢复补取，再复用接口验证自管云。管理员 Tutorial 列出各方案、注册材料、配置步骤与限制；正式 Module 尚未完成验收，独立原型结果只记入配套计划。

## 2. 数据与身份边界

| 对象 | 权威与作用 |
| --- | --- |
| 人员和组 | AD `anasIdentityAnchor` 是持久身份键；名称、DN、地址用于显示和查找 |
| 人员主地址 | AD 单值 `mail`，系统维护；附加邮箱默认地址不覆盖它或 OIDC `email` |
| 有效个人地址 | 个人别名最终保存于 AD `proxyAddresses`；邮件 Module 维护及排重受管 SMTP 地址，保留不归它管理的值；门户不提供地址维护接口 |
| 邮箱资源 | Samba 保存同一人员名下的稳定邮箱资源及人员归属，各箱共用人员登录；PostgreSQL 保存本地运行投影、固定协议身份、Roundcube 用户和存储引用；不把原始人员 anchor 投影为登录名或路径。AD 资源结构已确认，安装与写入协调进度见 D4 |
| 地址到箱的映射 | Samba 表达地址与稳定邮箱的归属，邮件 Module 协调占用及保留，邮件 Module 校验后生成本地投影；不能从同一人的全部 `proxyAddresses` 推断它们都属于主箱 |
| 邮件与队列 | DMS 保存本地邮件和队列，Roundcube 提供界面；Go 拉取的原始邮件暂存也位于本 Module 的 `DATA_PATH`，云端暂存源的留存另行显示 |
| 会话与操作 | Go/PostgreSQL 保存邮件会话、凭据关联、撤销和操作状态；DMS/Roundcube 按 Go 的结果执行 |

例：Alice 的 `alice@example.com` 和 `shopping@example.com` 属于 M1，共用收件箱和 Sent；`projects@example.com` 属于 M2，具有独立邮件和默认发件地址。M1 凭据不能进入 M2，也不能仅因同属 Alice 就从 M1 冒用 M2 地址。新增别名不创建邮箱，移除别名不删除已有邮件。地址维护不等于删除邮箱：原用户仍用同一人员登录，从管理页打开原 mailbox_id 对应的邮箱，访问原收件、已发、草稿和私人联系人。独立箱交出默认地址前先确认替代默认地址生效；一期不提供删除其唯一有效默认地址的动作。之后发送和回复使用当前有效地址，历史邮件中记录的旧地址不改写。

用户可自助开通本人的独立邮箱，管理员可代办；邮件服务端核验本人归属、受管域和统一地址占用，普通用户不能指定他人 owner。主邮箱仍由系统派生，不能借新增独立邮箱修改人员主地址。人员禁用或单箱停用后继续收件，但停止相应登录及发送许可；保留地址和邮件，不自动转让；建号冲突中的显式旧址移交仅按 R-068 处理，历史邮件不随地址转给新人员。

AD 与 PostgreSQL 不构成一项跨系统事务。AD 表达人员、邮箱和地址归属，数据库补充运行及执行状态；遇到冲突或未知结果，不以数据库旧快照覆盖 AD，也不直接认领一个只有 AD 地址、没有已确认邮箱映射的资源。Cloudflare 规则是这些受管地址的入口投影，不能反向覆盖 AD 或授予邮箱访问权；其失败恢复沿用 R-017/R-033，不另造人员或地址权威。

### 2.1 外部服务接入边界

| 路径 | 一期能力 | 部署前提与边界 |
| --- | --- | --- |
| Cloudflare Email Worker → 私有 R2 → NAS Go → DMS | 云端先保存原文与可信目标；NAS 每 60 秒拉取，可选通知触发立即取信 | Cloudflare 域、Routing、Worker、R2 订阅/私有 bucket、受限存取认证；NAS 只需出站 HTTPS |
| Cloudflare → 自管云持久暂存 → NAS Go → DMS | 云 Postfix 与云 Go 独立于 NAS 接收；使用同一拉取与通知语义 | 云主机公网入站 25、磁盘、TLS 与备份；不以有限 SMTP 延迟队列代替约定的离线保管 |
| 发件方 → NAS DMS（直接收件） | 管理员明确选择公网 MX 指向 NAS，直接 SMTP 交付；离线依靠发件方重试 | NAS 公网入站 TCP 25、正确 MX/A/AAAA、TLS 及安全收件配置；发件方不一定重试或长期保管，不能保证离线不丢件 |
| DMS → Resend | 认证 SMTP 代发、发送域验证指引、额度和投递结果反馈 | 使用 SMTP 接口及 Secret 中的 API key；无需另写 HTTP 发信代理 |
| DMS → 其他 SMTP 服务 | 同一配置入口接受服务器、端口、TLS 模式、凭据引用及允许发件域 | 逐服务执行兼容性验证；不自动承诺所有供应商功能 |
| DMS → 收件方 MX（直接发送） | 管理员明确选择后通过出站 TCP 25 投递；不需要第三方 SMTP 账号 | 检查发件 IP、PTR、SPF、DKIM、DMARC 和真实投递；未选择时不得自动切换为直发 |

入站和出站可独立选择；一期采用一个默认出站配置，允许受管发件域显式覆盖，每个域同一时刻只使用一个确定的出站配置。云服务不接管人员登录或 IMAP，Roundcube 仍向 DMS 提交，Go 仍负责当前箱与发件地址授权。

供应商管理都属于 Go 中间层：它持有受管 Secret 引用、调用 Cloudflare 路由 API、决定入站路径和出站服务、生成并核验 DMS 配置、汇总结果。DMS 执行 SMTP 接收、队列、重试和外发，Roundcube 负责读写界面；拉取模式由 Go 取得原始邮件，再经受限内部投递入口交给 DMS。管理归属不要求再由 Go 实现一套公网 SMTP 服务器，也不把云凭据交给 Roundcube。

本地邮箱就绪与公网地址就绪分别显示。目标验证信可在已通过本地身份/存储验收的邮箱读取；云端待验证不使公网收件变为可用，也不允许绕过 Go 登录。普通用户不能把投递目标改成外部私有邮箱，内部投递地址不列为可选发件身份或公司通讯录地址。

DNS 变更清单区分收件 MX、发送域认证和供应商回执/退信子域；接入发送商不能覆盖 Cloudflare 收件 MX。Tutorial 先提供管理员配置和核验，开通 R2 或部署自管云需显示具体资源及费用；不自动购买套餐或迁移 DNS 托管。套餐数字与接口事实见[接入研究 §11—12](../../docs/research/mail-routing-alias-and-module-access.md)，不将可变免费额度写成永久产品保证。

### 2.2 云端常态收件与每分钟取信

云端是常态入口，不等 NAS 断网后再切路由。自管云的投递域 MX/A/AAAA、TCP 25 与 SMTP 握手由独立外网探测；无探测点、探测器故障或过期证据显示未知，不能用 NAS 出站或本机监听代替。Worker/R2 检查 Routing 绑定、R2 存取和 HTTPS 拉取；NAS 入站 25 的状态不影响此路径的就绪判断。

Go 每 60 秒调度一次取信，不依赖用户登录；同一来源已有任务时合并唤醒，不并发重入，故障与限流退避显示实际延迟。NAS 离线期间云端继续保管已接收邮件，恢复后分页补取积压。60 秒不是端到端交付保证。云存储写入失败、容量不足、超出保管期限的行为必须验证，不能承诺无限离线不丢件。

拉取只接受当前仍有效且可证明的投递目标；先保存完整原文和接收记录，再经受限内部入口交给 DMS。来源实例、稳定消息 ID 和目标组成去重键；不按 To/Received、Message-ID 或已读标记猜归属和进度。结果未知保留核对状态，正文、附件及内嵌图片不重新拼装冒充原文。

管理员可显式切换两个已就绪的云来源；逐地址记录与回读变更，重启后继续未完成操作，旧来源仍补取积压，直到确认处理完毕。不得因 NAS 上线或 25 可达自动改为直投；切换不改变出站选择。未被任何来源接收、已过期或已丢失的内容不能报告为已恢复。

### 2.3 新邮件通知与交付确认

两种云来源都先持久保存原文及真实目标，再发送不含正文的新邮件通知。NAS 验证来源并持久记录任务后快速响应，立即触发原有拉取任务，60 秒补取持续运行。没有可达 Webhook 入口时可以轮询，但不能报告通知已就绪。网络认证、可信目标和 Secret 沿用 R-041/R-046。

服务器分开持久记录通知已接收和邮件已交付；只有 DMS 持久接收、本地完成记录已保存并回传经过验证的最终确认后，才记该目标交付完成。Webhook 2xx、下载完成或已读都不能代替它。通知超时保留待处理邮件，有限延迟重试与轮询并存；重试参数见计划 D9，不引入长时间同步等待或无限请求。

Webhook 与轮询复用同一来源消息/目标键及接收记录。正常重复通知、并发唤醒和确认丢失不得重新导入已确认项目；DMS 接收结果未知时核对，云回执丢失时只重发回执。确认记录、去重状态和云副本清理纳入既有恢复范围，旧备份与云端完成清单不一致不能伪报已恢复。SMTP 正文推送、已有邮箱 IMAP 拉取和 IMAP IDLE 不作为当前产品接入选项。

### 2.4 finance 初始化约定

2026-10-26 用户确认 finance 使用 `mail-poc.bengbu.cc.cd`，通过现有系统后缀迁移保留旧主地址。初始化须显式设置每人 2 个附加箱、10 个别名、每箱 2 GiB、每分钟 30 封。以上为 finance 的已确认部署参数，不改变其他部署必须由管理员明确设置限额的要求。

云暂存总容量为 2 GiB，已交付副本保留 7 天；容量不足先清理最老的已交付副本，仍不足则拒收并告警，未交付邮件不自动删除。通知已接收、已下载均不属于已交付；只有满足 R-057 的最终确认才能进入清理范围。此政策纳入 R-054/R-057/R-065 的验收，不允许用清理未交付邮件或静默超额代替。

## 3. 继承的仓库约束

以下约束继续适用，不在本矩阵重编号或降级：

- [目录主邮箱](../requirements/directory-primary-email.md)：`MAIL-R-001`—`007`；其中“不新增独立邮箱数据库或同步服务”约束目录字段维护任务，不禁止用户后来选择的邮件 Module + PostgreSQL。既有后缀更新能力不等于邮件迁移完成。

- [目录事件订阅](../requirements/directory-event-subscription.md)：只读日志、独立游标、最大传播时间、全量兜底及已有会话撤销。

## 5. 验收范围说明

R-002 用受控测试预配的公开地址变化验证持久身份，不能算自动改名功能。R-023 的 SMTP 判据是撤销新提交许可，不要求 TCP socket 必须立即断开；IMAP 则检查变更前已经认证的连接是否还能读取。已经下载到浏览器或客户端的邮件不属于远程可收回的数据。

R-024 的本地失效、应用发起 IAM 退出、IAM 后台通知分别测试；PoC 的本地退出通过不能代替正式双向登出。R-029—031 只接受同一一致基线的停机恢复，不声称在线一致性、跨版本恢复或无需协调其他共享数据库消费者。队列恢复检查消息身份与实际投递，不要求 Postfix 内部队列文件名保持不变。

R-034 覆盖已经形成的撤权意图，不承诺 AD 不可读时仍能获知尚未观察到的目录变更，也不将目标服务不可达计为已完成踢线。R-037 保留 R-031 的业务归属和操作记录，失效的是可继续授权的旧登录状态；不要求通过轮换人员 AD 密码完成失效。

R-040/R-041 的入口同步覆盖地址生命周期，不将多个箱汇入一个普通邮箱再按 To 头分发。首次目标验证由授权人员完成；无法自动完成的验证步骤如实显示等待状态。R-045 按服务实际 SMTP 状态判断重试或失败，不能假定免费月额耗尽时供应商会替本地保存邮件；发生接收确认丢失时不承诺 SMTP 端到端恰好投递一次。R-049/R-059/R-060 需要受控测试域、已开通账号及明确的测试收发地址，缺少条件标为阻塞，不将这一已确认范围移出验收。

R-050 的探测点不可用不等于云中转不可达，Worker/R2 不适用此 SMTP 探测。R-061 在正常空闲调度下验证 60 秒周期，接口退避、下载和外部交付延迟分别记录。R-052 的键区分来源、消息及目标，不误合并多箱投递。故障注入只作用于隔离测试源和 NAS，不改业务防火墙。旧 R-055 中的云来源原文、Bcc、地址撤销、重启和恢复检查继续由 R-041/R-052/R-058—062 覆盖；自动降级/回切仍取消，重新支持的显式 NAS 直接收件按 R-073 验证。

人员共用登录、本人开箱/管理员代办、停用后继续收件和管理员显式设置配额已确认；管理员确认的建号冲突旧址移交也已确认；具体部署值、AD 协调方案及云端保管边界仍见计划 D2—D9。它们不因出现在研究或本文解释中自动成为已确认产品承诺，也不豁免上表和继承规则。

### 5.1 建号地址冲突与管理员确认的地址移交

子邮箱及别名地址保存在 Samba，并按稳定人员 anchor 与邮箱资源绑定，共用人员登录。建号比较的是 `新用户名@当前邮件域` 的规范化完整地址，而非全域任意邮箱的 local-part；其他邮件域下相同前缀不单独构成当前主地址冲突。已有 sAMAccountName/UPN 冲突仍执行目录原有规则。

R-067 的“维护已有地址”不会自动扩大操作者权限：只有建号权限不能据此修改他人地址；系统主地址、受保护或保留地址仍受 R-003/R-014/R-016 约束。读取失败显示无法核验，不显示“无冲突”。2026-10-25 用户已明确允许管理员确认后把冲突旧址交给新用户，R-068 记录这一受限例外；不再把释放语义列为待决。移交保留历史归属，改变的是后续有效地址归属，不能继承原人员邮箱或把原箱内容搬给新用户。已确认的资源/地址占用结构按计划实施并验证原子协调与状态回读，不能用结构确认代替实测。
