# 分组共享清单要求

分组信息由所属 Module 的 `identity.groups` 声明，应用入口组从已有应用身份声明派生。已有动态能力名称可以引用声明模块发布的能力列表，须限定所属前缀；描述仍由该 Module 提供。Samba 维护 ANAS 通用组和已知 AD 内置组介绍。部署生成一个不可变共享 JSON 文件供消费者只读挂载，既有 CSV 输出为清单派生投影，不再维护第二份类别或介绍。

清单描述组的用途，AD 是成员关系、稳定身份和实际权限的唯一事实来源。系统内置组按 SID/RID 匹配，不能按名称赋予管理权；未知组使用目录原有介绍，没有时明确说明。清单不导入个人/服务密码，不提供目录写凭据，不因“受管”标签降低 AD 风险。

方案复杂度中等，复用现有 Module/部署编译与渲染，无新增服务或数据库；用户已确认。旧应用目录 APPCAT 及门户交互 PORTAL 分别保留自己的矩阵，不重复归属。

## 需求矩阵（规范来源）

| ID | 要求 | 验证方式 |
| --- | --- | --- |
| `GROUPCAT-R-001` | 分组显示信息必须由所属 Module 声明；应用入口组复用已有应用身份声明，动态能力列表只纳入所属 Module 的名称 | 单元 + 契约 |
| `GROUPCAT-R-002` | 部署必须生成单一共享清单，消费者只读挂载；CSV 等旧输出必须从清单派生，不得成为独立注册源 | 单元 + e2e |
| `GROUPCAT-R-003` | 清单每项必须包含稳定逻辑 ID、Module、实际组名和目录定位、类别、顺序、英文显示名/介绍与风险说明；支持简体中文，缺省回退英文 | 单元 + 契约 |
| `GROUPCAT-R-004` | Samba 必须以同一清单创建受管组及维护其介绍，不得改写系统内置组、成员关系或权限以适配元数据 | 原生隔离域 + e2e |
| `GROUPCAT-R-005` | 门户必须将受管声明绑定到实际目录对象，不得仅凭 APP_/CAP_ 前缀、名称或清单风险标签授权；目录原生风险判断继续生效 | 单元 + e2e |
| `GROUPCAT-R-006` | 清单必须拒绝重复/冲突定位、缺少英文介绍、不可信目录父节点、敏感值引用与可写/公开挂载 | 单元 + 契约 |
