# Module 资源运行方式要求

本文规定下一版本根据内存等资源选择 Module 运行方式的统一边界。**需求已确定，功能尚未实施；
不是当前 Immich 接入的前置条件。** “运行方式”指一组已声明的功能开关、并发和资源配置，
不是因内存变化自动把 Compose 改成 Incus，也不是持续自动调度。

设计见 [Module 资源运行方式](../../docs/architecture/module-resource-profiles.md)，
交付顺序见 [配套计划](../plans/module-resource-profiles.md)。

## 1. 范围与原因

用户要求同一套办法适用于所有 Module，而不只为 Immich 添加低内存开关。
现有 Module 已有配置类型、默认值、可选服务、条件 capability 依赖和变更应用方式。
新增能力应复用这些入口；只在公共规划器处理资源信息，不为每个产品增加硬编码分支。

所有 Module 都进入覆盖清单，但不强迫每个 Module 存在多种运行方式。
没有可安全缩减功能的模块可以只有默认方式，并明确资源建议未知或未经测试。
“单一默认方式”是合法结论，“从清单中消失”不是。

## 2. 选择与配置

默认保留现有部署行为。推荐是只读的，管理员选择后才通过既有 plan/apply 更改配置。
用户显式设置不能被一组推荐默认值覆盖；已有选择也不能因每次启动或当前空闲内存波动被静默改写。
功能关闭的影响要在计划里看得到，例如关闭本地 ML 不等于手机备份、缩略图等必要处理全部停用。

共同规划器处理声明和资源预算；Module 描述自身哪些配置组合可用。
不得发明新的密码、Secret、数据目录或权限覆盖通道。旧 Module 没有新声明时保持现有行为。
框架不统一迁移数据库、替换运行引擎，也不自动把数据发往远程服务。

## 3. 内存与预算口径

至少区分目标宿主总量、VM/容器有效上限、当前观测、明确分配预算和负载实测。
不能使用运行 CLI 的笔记本内存代替远程 Docker/计算目标；未知情况显示未知，不能按无限资源处理。
swap 不等同物理内存，容器硬限额不等同应用稳定需求，应用的堆限制也不等于全部进程 RSS。

规划需要预留系统/控制面、未纳管负载和已有工作区资源，不把整机 RAM 全分给应用。
共享 PG 等实例基础开销只算一次，各 Consumer 增量另外计入；不同实例不能因产品同名而被错误合并。
启动、导入、索引、升级和备份可能有不同峰值；未经声明可串行的工作不得按串行低峰估算。
所有经验值绑定版本、平台、工作负载和测量条件，缺少证据时不能升级为已认证支持。

## 4. 变更、安全与可恢复性

选择运行方式仍走配置解析、条件依赖、锁、不可变 deployment、现有生命周期和失败补偿。
同一份规划结果服务 CLI 与控制台，说明配置差异、功能变化、影响的依赖、资源数字的来源及需要的重启。
应用前重新确认目标和硬约束；失效的计划不能在不提示的情况下执行更激进的组合。

切换和回滚保留原件、数据库及身份绑定，不以清空持久数据换取省内存。
账号权限、TLS、Secret 隔离、网络策略和撤权保证不因运行方式而减弱。
远程计算需单独配置、能力与数据流向确认；未配置时不得自动退往公共端点。
临时目录仍遵循现有临时存储契约，不额外建立一套 tmpfs/清理生命周期。

## 5. 需求矩阵（规范来源）

本矩阵是规范来源，正文是解释。两者冲突以矩阵为准。

| ID | 要求 | 验证方式 |
| --- | --- | --- |
| `MODRES-R-001` | 本能力安排在下一版本，不得作为本版 Immich 接入的强制依赖 | 审阅 |
| `MODRES-R-002` | 覆盖清单必须由现有 Module inventory 派生，包含只有默认方式的 Module | CI |
| `MODRES-R-003` | 共同资源规划器不得通过产品名称分支决定某个 Module 的配置 | 单元 + 审阅 |
| `MODRES-R-004` | 未声明资源运行方式的旧 Module 在未显式选择新能力时必须保持原配置和服务集合 | 单元 + e2e |
| `MODRES-R-005` | 推荐的配置默认值不得覆盖用户显式配置，冲突必须可见 | 单元 |
| `MODRES-R-006` | 运行方式声明只能引用经现有 schema 校验的允许配置，不得注入未声明参数或 Secret 明文 | 单元 |
| `MODRES-R-007` | 规划输出必须区分可用、资源不足、条件未知和未验证，不得将未知状态标成已支持 | 契约 |
| `MODRES-R-008` | 内存证据必须来自实际执行目标及其有效限制，而非控制 CLI 所在主机 | 单元 + e2e |
| `MODRES-R-009` | 工作区预算必须扣除明确保留的系统/控制面、既有分配和非纳管负载预算 | 单元 |
| `MODRES-R-010` | 预算必须按实例身份去重共享基础开销，并单独计算各 Consumer 增量 | 单元 |
| `MODRES-R-011` | 发布的资源建议必须带有版本、平台、负载和证据状态，未测量值不得标为实测 | 契约 |
| `MODRES-R-012` | 规划必须分别表达物理内存、硬限额、预算、当前观测和 swap，不得相互替代 | 单元 |
| `MODRES-R-013` | 未被明确约束为串行的任务峰值不得通过假定串行而从预算中省略 | 单元 |
| `MODRES-R-014` | 推荐与 plan 计算必须只读，不能启动服务、写配置或安装依赖 | 单元 |
| `MODRES-R-015` | CLI 与控制台必须消费同一规划结果，包含有效配置差异、功能影响、依赖和重启影响 | 契约 |
| `MODRES-R-016` | 已选运行方式不得因启动、重启或内存波动而自动切换，变更须经过显式 plan/apply | e2e |
| `MODRES-R-017` | apply 必须重新校验执行目标与必要硬约束，条件失效时拒绝原计划而非静默另选 | 单元 |
| `MODRES-R-018` | 运行方式变更必须复用现有配置、锁、deployment 和生命周期入口，不得另建执行状态机 | 单元 + 审阅 |
| `MODRES-R-019` | 切换失败与重试不得丢弃原图、数据库或持久身份绑定 | e2e |
| `MODRES-R-020` | 回滚必须恢复冻结的配置和运行方式意图，不得重新按当前空闲内存选择默认方式 | e2e |
| `MODRES-R-021` | 每个声明可用的运行方式必须通过其明确保留的核心业务流程，不能只以容器健康为验收 | e2e |
| `MODRES-R-022` | 资源不足或方式切换不得降低认证、Secret、TLS、网络隔离或撤权要求 | e2e |
| `MODRES-R-023` | 远程计算方式没有显式目标和数据流向授权时不得启用或自动回退到外部服务 | e2e |
| `MODRES-R-024` | 运行时不支持声明的资源限制时必须报告未生效或拒绝，不能显示成已强制限制 | 契约 + e2e |
| `MODRES-R-025` | OOM、资源证据失效和配置漂移必须沿用现有状态/问题记录入口，不能以推荐值冒充运行观测 | 契约 |
| `MODRES-R-026` | 新增 Module 或资源声明变更必须触发覆盖清单和对应验证证据的过期检查 | CI |
| `MODRES-R-027` | 4GB 等容量支持结论必须绑定整套已启用依赖和代表性负载的测试，不能用空载单容器通过替代 | e2e |
| `MODRES-R-028` | 所选 Provider 方式不能破坏已绑定 Consumer 的必要能力；冲突必须在应用前阻塞 | 单元 + e2e |
