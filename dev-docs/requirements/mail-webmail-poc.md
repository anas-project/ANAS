# DMS 与 Roundcube 组合验证要求

用户于 2026-10-23 确认优先验证 DMS + Roundcube 的统一登录、别名发信和数据恢复，再判断是否优于成套邮箱方案；本次测试主机明确指定 finance。本文只约束选型实验，不表示已批准生产邮件 Module、云端路由联动或新增身份同步服务。

实验使用独立 Docker、网络、测试域和合成邮件。统一登录必须实际经过现有候选 IAM 的原生实现和浏览器，不以伪造 token 或模拟登录端点替代。目录身份和主地址沿用既有 DIRKEY/MAIL 规则；如果原生产品不能满足，记录失败和所需适配，不把测试专用手工映射说成生产自动同步。

别名验证覆盖同一邮箱的多个收件/发信地址，并分别观察 SMTP 信封和可见 From 的授权。恢复验证从空的独立目录开始，证明恢复的是邮件、归属和 Webmail 状态，而不仅是容器能启动。仅按停止服务后的备份验证，不承诺在线一致备份。邮件内容按本轮已确认决定保存于 data。

不在本次范围：公网 DNS/MX、Cloudflare/SMTP2GO 实际接入、生产 AD/IAM 变更、Portal 别名 CRUD 正式实现、邮件 Module 发布和所有 IAM Provider 的全矩阵验收。比较成套方案以有来源的组件/接口/恢复差异为准；未运行的产品不得填写实测资源或通过结论。

本矩阵是规范来源，正文是解释。两者冲突以矩阵为准。

2026-10-24 用户进一步确认 Go 中间件统一管理身份、主邮箱、别名和独立邮箱，并明确在 `whl@finance.hlong.wang` 验证可实现性。本轮追加隔离 Go + PostgreSQL 原型、Roundcube 薄插件和 DMS 授权适配，不实施生产 Module。Go 复用真实 IAM 的 OIDC 登录，向当前选中的单个邮箱签发凭据；个人别名写入测试 AD，再形成投递与发信授权状态。独立邮箱拥有自己的收件箱、已发送和发信地址。

主地址生产变更仍未实现，只为未来 sAMAccountName 变更预留。R-004 的追加验证使用显式测试预配改变公开地址，检验固定内部邮箱身份的兼容性，不把手工预配说成自动改名工作流。新架构的数据备份和全局 IAM 撤权仍需独立复测，原生组合历史通过结果不自动转移。令牌撤销后的已有协议连接行为须如实记录。

2026-10-24 用户确认继续验证：一期接入 AD 用户、组和只读公司通讯录；组内与全局共享联系人作为二期，只保留可扩展的通讯录来源与权限接口，不实现共享联系人 CRUD 或共享权限界面。验证继续使用 finance 独立测试域，覆盖真实目录事件、已有邮件连接撤权及重新启用后的旧会话，目标为依赖健康时 60 秒内收敛。原生 IAM 后台登出与 Go 本地退出也须分别验证，不能用直接删除数据库记录代替事件链路。
