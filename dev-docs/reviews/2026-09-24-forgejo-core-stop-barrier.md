另外复现空 ownership 标签被丢弃、同名非 Compose 容器可能进入停止路径的问题。

必须匹配确切 Compose 项目及服务标签，然后只向所观察的不可变 ID 发送固定停止命令。

补偿路径也曾绕过清理：候选停止失败时默认恢复旧版本，或备份失败时自动重新启动，
会覆盖退出证据并重新接收任务。新增类型化停止错误，原停止失败和候选回滚清理失败均
阻止自动 previous_restore；普通 Compose 错误保留原恢复策略。备份在声明 Hook 之前
持久化 cleanup_pending，进程中断或清理失败时保留记录，不自动启动；记录清除写入失败
同样不得让内存误认为已完成。重新打开事务的回归验证该边界仍成立，恢复流程不被冒充完成。

## 备份清理意图的持久化修复

代码复核发现旧通用YAML写入使用固定`.tmp`，只同步文件而不同步重命名目录。新增回归
分别复现其跟随预存临时链接覆盖其他文件、缺少目录同步、同步失败仍可进入Hook的问题。
备份日志现在使用局部的强化写入器，复用securefs私有目录/单链接校验、完整写入和父项
同步；临时文件随机排他创建，先同步数据，再核验目录与旧记录身份、原子替换、同步目录
及新建父项。同步失败时不执行Hook，已发布的pending记录保留用于保守恢复。

该改动仅用于备份停止事务和清理标记，不重定义所有历史YAML快照。链接、硬链接、开放
权限文件和目录替换均拒绝；旧固定临时项不覆盖或自动删除。文件/目录同步故障注入、真实
临时文件回归以及重开pending拒绝已通过；它不是实机断电、完整备份恢复或正式升级矩阵
的验收声明。此前运行工件不被归因于这项随后新增的修复。
