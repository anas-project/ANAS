## 实现边界

`WorkspaceStateStore` 包装原 FileStateStore，工作区读取器装配强制使用它。原有工作区
`.anas/state/lock` 先以独占方式建立持久标记，绑定原 HTTP 日志目录路径摘要和设备/inode，
同步文件/目录后降为共享锁，保护整个生命周期和失败重试。每个外部步骤复核目录/锁/标记；
原 journal 仍保存发布/退役事实，不增加第二份任务数据库。

普通回调结束、空 publications、进程退出、操作返回成功都不清除标记。正常 Controller 停止
或显式 Executor.Recover 必须完成既有顺序和完整库存，托管 owner 还须关闭原读取器，才能
清除并同步标记。清理失败保留两个锁；资源关闭失败后即使 session 退出也保留标记。进程死亡
只释放内核锁，不擦除待恢复状态。错误/缺失/替代 journal 和同路径重建的目录不能自动采纳。

Runner 的实际独占锁在竞争期间和拿锁之后检查原描述符，覆盖独立 `credential rotate`、
`admin local rotate` 及应用层直接写调用和锁内恢复。非空字节一律拒绝，不跟随其中路径，
不把未知标记清空。共享读保持原行为；需要写入迁移/恢复的“读”入口仍受保护。原运行目录
初始化仍可能先发生，不宣称拒绝前绝无任何文件系统调用。CLI 不会自动要求后台排空，也不
把 `--force` 变成绕过围栏的选项。

文件日志读取同时补单硬链接/current-owner/no-follow 与关闭错误检查，避免恢复时把外来
文件视为原 journal。未改变业务状态 schema；锁文件新增的是未发布的合作进程协议。旧 writer
可能忽略标记，不能声称向后安全兼容；不得带未清理标记降级或删除证据。
