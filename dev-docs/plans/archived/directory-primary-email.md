## 6. 建号对象所有权补查（未作为已完成安全隔离）

finance Samba 4.23.6 的临时 OU 实验已观察到：仅显式授予 user Create Child 的创建账号，会成为新用户的对象所有者，并可经原生 LDAP 修改该对象的访问控制表 DACL。故“只授予 CC”不等于该账号后续仅能 Add。给临时 OU 添加继承的 Owner Rights（SID S-1-3-4）只读规则后，规则确已继承、域管理员显式权限保留，但创建者仍能修改 DACL；该配置未施加到正式人员 OU，不能宣传它已提供隔离。所有实验对象均删除。

已知风险是后续将此类人员升为域级账号时可能保留创建者的控制权；finance 的实际提权后状态未验证，不能宣称已证明真实域接管。自动审批拒绝了在真实域把一个新测试用户临时加入 Domain Admins 的验证，理由是失败清理可能留下高权主体；此动作未执行。随后改用完全断网、无发布端口、无信任关系的独立 owner.test 假域作为安全替代。该假域前两次未启动 LDAP，原因是匿名 Docker 卷中的 SYSVOL 文件 ACL 初始化被拒；容器/卷均删除，不以失败初始化认定所有权结论。最终只测试 LDAP 的原生初始化路径成功，结果见 §6.1。

此项补查不扩大已确认的产品验收 ID，也不把新风险悄悄当作通过；若需要在加域级组前增加“本人域绑定移交所有者、回读、再加组”的分步处理，将按 AGENTS.md 的多阶段设计确认规则先向用户确认。现有原生域组保护、后台创建绑定与个人验证路径的组合边界在完成此判断前不宣称验收通过。

### 6.1 隔离域结果与方案确认

安全替代实验使用候选 Samba 镜像 `d058b9387b37…`，新建 `owner.test`，网络模式 `none`、无发布端口、无生产信任关系。通过原生 Python provision API 初始化 LDAP（`skip_sysvolacl=True`，因此不作为 SYSVOL/SMB 验收），避免了匿名 Docker 卷上的文件 ACL 初始化问题。普通人员和加入该假域 Domain Admins 后，创建者都是 owner 且均可修改 DACL；组成员关系已回读确认。整个假域容器和匿名数据卷已移除，未在 finance 真实域执行被拒绝的提权动作。

**新增方案待用户确认，尚未实现**：在将门户创建人员加入域级权限组前，复用操作者本人 LDAPS 绑定移交对象所有者到 Domain Admins，回读成功后再加组；第一步未知/失败不继续，第二步失败要分别报告所有者与组结果，不回退成不安全的所有者。两步均使用目标 GUID、近期 OIDC、当前角色/原生 ACL、一次性确认和审计；不保存本人密码、不添加后台高权凭据、服务、数据库或 Casdoor 补丁。仍不承诺外部 AD 管理工具并发下全局原子性。新增部分复杂度中等：所有者读写、确认参数及部分成功处理均需覆盖；按 AGENTS.md 多阶段执行的确认规则已发问。另一个选项是明确暂不启用门户建号，不能默默缩小已确认验收范围。
