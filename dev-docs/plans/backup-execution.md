# 备份与恢复统一执行实施计划

验收依据是[备份与恢复统一执行要求](../requirements/backup-execution.md)的需求矩阵。本文只回答「先做什么」，
不复述验收标准。

## 1. 给实施者

**当前状态：未开始。** 2026-09-28 按操作者同意的方案立项。

依赖：

- job 记录与合流依赖[统一动作 ABI](action-abi.md) 的 job 模型与单一 job 存储；
- hostd 执行依赖[宿主特权动作通道](host-action-channel.md)。新增的宿主动作按 `HOSTACT-R-012` 回答五问，
  并进入动作清单；
- 目的地临时目录误删的修复已在独立会话进行，合入后按 M1 验收。

## 2. 里程碑

| 里程碑 | 需求 ID | 状态 |
| --- | --- | --- |
| M1：目的地并发安全 | R-011、R-012 | 未开始 |

| M3：job 记录与合流 | R-001、R-003、R-005、R-006 | 未开始 |
| M4：CLI 在线提交与离线执行 | R-002、R-004 | 未开始 |
| M5：hostd 执行与恢复确认 | R-007、R-008 | 未开始 |

### M1：目的地并发安全

- [ ] 临时目录写入归属记录（主机、启动 ID、进程、心跳时间），清理只删除被证明已废弃的临时目录
- [ ] 在共享与网络文件系统上验证两台主机同时备份到同一目的地

### M2：统一目的地登记

- [ ] CLI 读取与控制台相同的 `backup_targets` 登记并按 ID 选择；未登记路径改为显式选项
- [ ] 控制台列表包含 CLI 写入登记目的地的备份

### M3：job 记录与合流

- [ ] 备份类操作进入统一 job 存储，定义合流与拒绝的参数键
- [ ] 离线执行的记录方式，以及 anasd 启动时对离线 job 的处理

### M4：CLI 在线提交与离线执行

- [ ] CLI 判断 anasd 是否在运行，在线时提交到队列并跟随 job 进度
- [ ] 离线路径的端到端验收，包括新主机恢复

### M5：hostd 执行与恢复确认

- [ ] 特权步骤作为编译动作接入 hostd，并通过五问评审
- [ ] 恢复的 plan 与一次性确认，绑定所选备份和目标工作区

### M6：宿主串行与写任务协调

- [ ] 同一宿主上 create/restore 串行排队，verify 与列表可以并发
- [ ] 经 anasd 执行时，作为工作区写任务进入领取前协调

## 4. 待决

- CLI 在线提交需要控制台会话；现有 `anas host` 命令经标准输入传入会话，备份命令是否沿用同一方式。
- 以什么判定「anasd 在运行」：执行租约 `jobs.execution.lock` 是否被持有，还是 API 是否可达。
- CLI 离线执行期间 anasd 启动时的行为：启动失败后重试，还是等待离线 job 结束。
